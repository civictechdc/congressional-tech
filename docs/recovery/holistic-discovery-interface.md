# Discovery slice interface (implementation in progress)

`corpus_recovery.discovery.Response(status, body, complete, evidence, content_type='', final_url=None)` is returned by `call(kind, url)`. Kinds are `cdx` and `replay_raw`; capture must reserve and record every call, enforce response-byte limits, retain evidence, and return exact bytes. `webharvest_lookup(original, collection, call, parse_cdx=..., url_key=..., max_pages=..., page_size=...)` uses the maintained `scripts/webharvest/webharvest_cdx.py` parser and key; it returns `complete`, `reason`, `candidates`, and per-page `evidence`. A complete negative applies only to the specified URL and collection. `acquire_wayback` validates exact identity replay before passing the raw response through; it requires capture to report the exact final URL and does not qualify or import it.

`relocated_search(target, stems, allowed_hosts, search, seen_identities, max_queries=..., max_pages=..., max_candidates=...)` returns candidate leads and evidence without fetching candidates. `search(query, page)` must account for calls and return candidates, evidence, complete and next_page. Pass URLs already covered by inventory or the attempt journal in `seen_identities`. `govinfo_document_candidate` generates only a lead from an explicitly matched CDOC package identifier; no relationship is accepted here.

Fixture entry point: `PYTHONPATH=packages/corpus_recovery/src:scripts/webharvest python -m corpus_recovery.discovery fixture.json`. No network calls are made by this fixture route. Source responses and bodies belong to capture/campaign custody; this module creates no persistent artifacts or cleanup duties. Adapter output remains a lead until the recovery owner's acceptance and importer consume it. This interface is provisional until integration and tests complete.

Sources: https://github.com/internetarchive/wayback/blob/master/wayback-cdx-server/README.md (resume keys); https://www.govinfo.gov/help/cdoc (package PDF format). Web Harvest behavior must be qualified separately against its deployed service.

Remaining work: campaign and capture owners must connect the callbacks and persist their evidence, use actual inventory/attempt identities, and drive candidates through acceptance/import. The Wayback function validates and fetches an already identified replay; it does not query Wayback CDX or verify the returned digest. No House legacy mapping is implemented, and the CDOC helper requires caller-supplied identifier evidence with no semantic identity validation. Additional tests are needed for every boundary, including budget exhaustion, budget exhaustion, digest evidence and further pagination failure modes. This is an incomplete slice, not a campaign-ready implementation.

`govinfo_bill_candidate` constructs a BILLS PDF lead only when supplied evidence identifies the exact Congress, type, number, and version; mismatches return no candidate. See https://www.govinfo.gov/help/bills. This does not itself validate the evidence or establish document identity. `Response.final_url` must be the actual final URL for a Wayback replay; redirects or missing final URL are refused.
