## Patch summary and practical value

T3 replaces a full hash/cloud/protected-version scan before every immutable upload with local ownership/stat checks and a maximum 30-second cloud allowance (`scripts/recovery_guards.py:97-118`). Raw index writes still receive a full boundary check through `scripts/dispatch_corpus_recovery_import.py:154`; protected versions are checked against the freshly loaded baseline and the importer's own updated ETags at lines 135-139. This removes repeated expensive work without making immutable uploads count as publication.

T8 supplies a small local command supervisor with pinned preparation, explicit working directory, persistent stdout/stderr, actual child wait results, and explicit resume (`scripts/run_corpus_recovery.py:57-171`). It removes the need to infer success from process disappearance. It does not supply corpus-specific recovery of remote write state.

T9 merges sealed input metadata and receipt records once, deduplicates identical records and bodies, ignores unrelated historical mappings copied into old `accepted.json`, and applies a count/time gate (`scripts/coalesce_corpus_recovery_batches.py:32-109`). It performs no body compression, body reads, catalog rebuild, or network request.

## Data flow and invariants

- **Cloud allowance:** `_cloud_at` is created empty in guard construction, cleared before a refresh, set to scan start only after successful bounded verification, and used only by that guard instance (`recovery_guards.py:68,86-95`). Boundary checks force a new scan and reject elapsed time after protected checks (`:111-118`). It is an observation of cloud state, not an atomic remote writer lock.
- **Protected baseline:** dispatcher saves complete baseline bytes and ETags before constructing its guard (`dispatch_corpus_recovery_import.py:111-125`). `protected_check` compares remote versions with those baseline ETags or importer-updated index ETags (`:135-139`). This preserves the conditional-index-write defense; no shared-state check is cached for mutable writes.
- **Pins:** dispatcher records code/input hashes, including external readiness/readback evidence where present (`dispatch_corpus_recovery_import.py:89-102`). The guard caches stat identities solely to avoid rehashing unchanged files during immutable uploads, while phase/shared boundaries force all hashes (`recovery_guards.py:76-84,109-115`).
- **Process state:** runner preparation records argv/cwd/pins; each attempt records preflight before launch and dispatch identity immediately afterward (`run_corpus_recovery.py:65-81,138-151`). Only an actual saved wait result can produce local `complete=True` (`:100-104`). A SIGKILL before identity persistence remains indeterminate and blocks another launch (`:93-94,127-128`).
- **Coalesced content:** input files are verified and their hashes retained in `coalescing.json` (`coalesce_corpus_recovery_batches.py:43-44,75-80`). Recovered URL/body pairs select relevant mappings; historical accepted rows outside those pairs never enter additions (`:45-59`). Identical receipt records are deduplicated by full canonical content, with input and distinct counts both recorded (`:64-66,78-79`). Existing baseline rows retain all metadata (`:67-73`). Final capture/body coverage is checked at line 97.

## Outstanding limits and untested risks

- **Local supervision only:** `status.complete` means saved child-wait exit zero plus no matching live child (`run_corpus_recovery.py:100-104`). `reconcile` explicitly returns `remote_state_verified=False` (`:114`), and resume executes caller-provided argv (`:142`). No corpus-specific remote reconciliation/resume phase is implemented here. Do not describe this as end-to-end resumable publication.
- **Cadence requires an invoked caller:** the CLI gate is wired, but there is no scheduled caller in this patch. A 15-minute threshold does not itself establish a 15-minute publication guarantee; the operational monitor, cloud-writer clearance, build time, and readback remain outside the evidence.
- **Input selection matters:** coalescing ignores old accepted-only mappings, as tested. It treats every supplied `recoveries.json` pair as an explicit current addition (`coalesce_corpus_recovery_batches.py:52-59`). It does not track previously consumed batches or tombstones for URLs deleted after an earlier recovery. The caller must select current unpublished additions and preserve authoritative deletion/rebase evidence; this review does not establish safety for replaying arbitrary previously published cumulative batches.
- **The cloud check is not a distributed lease:** status requests and protected HEADs are observations. A cloud writer can start after the check. Conditional index writes and the subsequent publication verification remain required; tests use an injected conditional store rather than live R2/GitHub behavior.
- **Remaining focused gaps:** no test directly exercises external-readiness expected-version mismatch, readback-report hash mismatch through the full dispatcher, identical-body/different-metadata baseline preservation, actual SIGKILL between spawn and identity persistence, or a child that ignores SIGINT indefinitely. Static paths fail closed for the first three relevant validations, but they are not runtime qualification.
