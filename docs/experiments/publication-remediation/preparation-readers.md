# Preparation readers, review batching and resource ownership

Local bounded evidence, 2026-10-18. No production rebuild or publication ran.

Publication and the offline identity CLI request `Catalog(search_indexes=False)`. They retain the same grouping, facets, preferred source, API/video classification and published values, while omitting search filter strings. Reviewed source masks initialize only when reviewed search needs them. Positional/document indexes are reused by binding without weakening complete member multiset comparisons. The binding complexity statement now includes member sorting. Source/group buffers use uint32 arrays, ID shards write to owned buffered streams, and navigation writes/verifies every tuple/member through bounded reads instead of retaining whole navigation/readback copies.

A 25,000-source/5,000-document fixture recorded 12,560,384 retained Arrow bytes for normal search initialization and 11,035,072 for publication initialization, with 1,525,000 filter bytes omitted. Measured constructor times were 0.418 s and 0.380 s; Python peaks were effectively unchanged. Separate process peak RSS was 153,239,552 versus 145,866,752 bytes, a noisy process-level observation rather than a derived guarantee. The 200,000-source navigation fixture preserved exact SHA-256 output hashes and reduced tracemalloc peak from 8,973,165 to 992,970 bytes. Its traced runtime increased from 2.008 to 2.409 s. These measurements describe a memory/time tradeoff on these fixtures, not production savings.

Review access validates source-row bounds before position lookup. Complete requested rows group by Parquet row group under the existing shared-reader lock. A 32 MiB cache jointly budgets complete source/document Arrow tables; oversized groups have one-operation lifetime and never enter the retained cache. This bounds retained cache bytes, not PyArrow's internal allocation while decoding one oversized row group. Closing a Catalog clears that cache and closes both readers. Constructor failures also close already-open readers.

The three-page review-export fixture needs two decodes: one source group containing both members and one document group, compared with individual-member reads decoding the source group twice. A snapshot-issued selection binds exact complete document/member objects and is reused across body/text/page evidence. The export fixture performs one complete selection instead of selecting again per evidence request. Every evidence request still checks snapshot identity and exact evidence bytes/signatures. Copied/foreign selections do not grant reuse. Existing independent reviewed-search, complete-row matching, withdrawal and evidence-hash tests remain green.

Block writers have explicit finalization and abort behavior. Flush failures close the stream; abort does not flush unfinished logical rows. Observation success descriptors write only after full readback verification. Source/document readers, detail readback readers, observation-count generators, export baseline streams and fetch responses have explicit lifetimes. Cleanup errors become notes on the primary exception. Fetch stages and verifies a complete selected pair before installing immutable names and replacing the local selector; interrupted or corrupt downloads retain named failure evidence and leave the prior selector unchanged. The review install lock is ignored at its exact build-owned path.

Validation: 102 tests passed across review publication/binding, local viewer, independent review search/viewer, observations, catalog pair validation and typed details. Injected failures cover second writer/reader acquisition, serialization, compression, write, readback, close, interrupted download, malformed selector and corrupt downloaded bytes. The shared-reader test now also observes fewer actual decodes while retaining the concurrency assertion. The receipt `evidence/preparation-memory.json` and script `scripts/measure_preparation_resources.py` preserve measurements. Decoded-memory budgeting and alias-index spilling remain separate pending tickets.
