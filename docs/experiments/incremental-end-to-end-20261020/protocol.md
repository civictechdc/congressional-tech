# ct-2ukk integrated fixed-change protocol

Written before collecting end-to-end measurements. This protocol authorizes local generated-fixture measurement only.

Decision: determine whether the integrated raw → catalog → viewer publication path limits repeated work to the same small change when unrelated source/catalog/publication content grows tenfold. Do not close the ticket from isolated raw/catalog experiments or from a narrow passing fixture.

Hypothesis: the same one-source append and one-source state correction should preserve unrelated values, IDs, and publication payload hashes. Logical native reads/submissions and app-store calls/bytes may vary with finite routing depth or mixed-leaf occupancy; corpus-proportional work remains visible and must be reported rather than called constant-cost. No speed or remote throughput claim follows from this fixture.

Arms: the same integrated code at 1× = 32 unrelated independent source documents and 10× = 320 unrelated independent source documents, plus one fixed target. The growth factor changes only unrelated records. These sizes cheaply expose broad work or mixed-leaf amplification without increasing configured row/byte budgets.

Cases: initial fixture selection, then (1) append one new meeting receipt/source URL and its pending URL state, and (2) correct the original target's URL state from pending to request_failed, preserving its source identity and all publisher evidence. Receipts, URLs, labels and correction values are synthetic and identical across arms. There are no retained document bodies or body-reader results; the fixture explicitly qualifies the known empty reading inventory through the maintained raw owner.

Maintained path: RawStorage.prepare/publish over LocalStore; raw_catalog.update_from_raw; viewer_publication.native.prepare_native_output with the existing synthetic no-review builder pattern; publisher.prepare_recovery and publisher.upload, including immutable payload writes/readback and conditional local viewer selection. The remote adapter is the existing fixture client backed by current local source objects. No catalog computation, grouping, rendering, validation or publication policy is reimplemented.

Held constant: maintained default application row/byte budgets, input structure and literal target/append values, exact code/runtime, decoded renderer policy and compression, no provider latency, no source HTTP. Initial population and first viewer publication are setup costs and recorded separately. Each changed phase starts with fresh application owners against exact selected roots; the fixture native transport retains its completed tables in memory. Run two repetitions per arm if the first pair completes without a correctness blocker. Stop after 20 minutes or three fixture preparation failures; retain all failures and revisions rather than replacing unsuccessful observations.

Measurements per phase: logical native Run calls, submitted Arrow rows/bytes, unique created Runs, exact-pin read calls/Arrow rows/bytes; LocalStore read/put calls and full body bytes (plus separate key-list/version counters); viewer fixture get/put/download calls and body bytes; wall time; measured tracemalloc current/peak bytes. Report existing resident fixture tables and Python allocation measurement scope. These are application boundaries, not OS I/O, actual native-engine CPU/memory, physical cloud requests, remote throughput, GitHub artifact transfer, or hosted attempt/journal overhead. The source-store reads and fixture-client GETs are nested boundaries and must not be summed as independent network cost.

Checks outside timed phases: preserve exact selected old source/document values and mappings; validate new raw state values; assert the append adds precisely its expected source/document and the correction changes only derived state fields for the fixed target; compare unrelated current source/document rows exactly; reopen old selected native roots and compare every field; confirm every previously published immutable object is unchanged and identify reused payload references/hashes for unrelated documents. Save exact selected manifests, per-phase counters and explicit refusal/error evidence.

Upgrade scope: source-contribution qualification/named global source-rule upgrades and explicit renderer upgrades intentionally enumerate complete selected inputs. They are separate operations from this fixed-delta test. Inspect their continuation bindings and existing focused tests; do not rerun a global upgrade merely to make this fixture pass. A changed interpretation or rendering requirement that refuses ordinary reuse is a reported qualification blocker, not permission to rebuild or alter policy/limits.

Decision rule: all correctness checks must pass before interpreting costs. A failed correctness/selection guard blocks qualification. If unrelated payloads or values change, report not solved. If logical work grows with corpus size, report each growing phase and its mechanism (including finite shared-leaf read amplification); do not claim constant work. Stable changed-path counts with preserved outputs establish only a bounded result on these generated cases. Timing differences are descriptive with two repetitions, not a statistical performance result or production acceptance.

Harness revision after retained attempt-1: the existing publisher release-identity helper imports from `scripts/`, which was missing from the standalone harness import path. The first 32-row setup reached viewer upload and refused with ModuleNotFoundError before publication writes. Added that repository import path only; no criteria, application code, defaults or policies changed. Attempt-1 and its partial measurements remain retained and excluded from completed growth comparisons.

Pre-run revision after retained attempt-2: the 32-unrelated case completed append and correction publication, but the strict unrelated-row checker refused correction because that fixture introduced `state_checked_at` for the first time. The maintained nullable-schema evolution added that field with null values to unrelated logical rows. To isolate a value correction without changing schema, include an initial deterministic `checked_at` on every initial/append state; correction updates it. Equality criteria stay strict. Preserve the earlier refusal and its complete phase counters. No application change is justified by this fixture issue.

Arm-size revision before collecting the comparison: use 4 unrelated documents versus 40, preserving the exact 10× unrelated factor and all maintained limits. Initial 32-row setup measured about 18 seconds and 825 logical source-observation reads; a larger setup risks dominating the protocol bound. Four/forty is the smallest cheap informative comparison here. The initial observed repeated mixed-leaf work and all partial 32-row results remain retained; this revision does not erase or classify them as a passed growth comparison. Run two fresh-process repetitions per arm. The parent explicitly accepted this smaller informative fixture before measurement.

Supplementary verification revision after all four attempt-3 cases completed: retain exact raw selection JSON and logical capture/state Parquet snapshots and explicitly compare every new raw value and row order against the generated inputs, in addition to the already passing old-root and derived-state checks. These checks run outside the timed phases and do not change the application path, cases, limits or equality requirements. Run one supplementary fresh-process case at each size and retain its measurements alongside the two earlier repetitions; do not discard the earlier observations or select the fastest run. No broad suite or production operation is needed.
