# Catalog update simplification

Decision: adopt a simpler bounded row-processing path and require explicit rebuilds to reinterpret saved metadata.
Hypothesis: avoiding writes during reads, saving each changed batch once, and reducing repeated metadata passes improves table-build runtime without changing explicit-rebuild outputs or losing capture evidence. Routine updates should retain existing metadata despite implementation changes.
Arms: frozen current congress_api source versus candidate, on the same saved Parquet sample; use the existing complete-record/schema comparison functions.
Cases: deterministic whole-document sample from the retained 671,035-row local snapshot, plus existing source-context, alias merge/split, failure and metadata-preservation fixtures. The sample is diagnostic, not a hosted full-corpus qualification.
Held constant: Python environment, source input bytes, one filename worker, body inspection disabled, two fresh-process runs per arm; no network. Bound each measured run to 10 minutes and scratch storage to available local space.
Decision rule: exact record and field-schema equality for explicit reinterpretation, preservation regressions passing, and at least 20 percent median runtime improvement with no material process-memory increase. If this fails, retain measurements and revise the intervention before adoption. No-change routine updates must read no receipts/bodies and publish nothing, including after code changes. Explicit rebuild must apply current rules.

Revision after the user's storage question: compare a typed Parquet batch store for sequential filename-row passes with the frozen baseline. Keep indexed lookups separate; do not replace one general-purpose row-object database with another. The first SQLite candidate ran alongside tests and is diagnostic only, not a qualifying timing. Any adopted Parquet path must pass the same exact-output and runtime/memory gates. Preserve failed arms.

Revision after the user's ordering requirement: replace repeated batch rewrites with a dependency-ordered stream. Restore prior filename/body metadata in one projected scan, discover shared facts while consuming source rows, write each temporary Parquet batch once, then read it once into grouping after all aliases are known. Preserve the earlier format-only arms as rejected diagnostics: they were faster on the sample but increased peak memory. Compare this complete intervention to the same baseline, with exact record/schema equality and the original runtime/memory gate; do not attribute its result to the storage format alone.
