Catalog filename replay review
==============================

Findings
--------
No blocking code defect was found in the tested comparison path. This review
approves the local tooling, not the historical replay's eventual result or a
production release. The full historical run is still in progress at this
checkpoint; its actual differences must be inspected before drawing conclusions.

The first integration test correctly detected an inconsistent fixture: two
records without retained bodies claimed body_format=pdf. Replay dropped those
unsupported body readings, and the protected-evidence comparison refused to call
the result preserved. The fixture now records body_format only for retained
bodies. The comparator remains strict; the failed assertion was not weakened.

Operational limit: disk space is checked before writes and during source-row
consumption, but that is not an enforced ceiling during cache restoration,
grouping or comparison. See CATALOG_REPLAY.txt. Large runs require live progress
and free-space checks. This local workflow does not automatically resume failures.

Data flow and invariants
------------------------
H1: filename replay cannot mutate the input catalog. CONFIRMED in code/fixtures:
source paths are read-only; all writer paths use a new isolated root. Input path
selection and hashes are rechecked after the output comparison. No publication
function is called and neither root receives a new selector.

H2: a subset or historical pair cannot qualify the current publication. CONFIRMED:
local_catalog_paths and validate_document_indexes check the complete pair.
publication_gate binds a matching 3.1.0 pair to saved verified public manifests.
Without that evidence run refuses unless --rehearsal is explicit, and all output
retains the rehearsal and publication flags. No outcome automatically approves
release. This does not establish completeness of an arbitrary legacy pair;
only the verified selected publication establishes that external boundary.

H3: grouping and evidence losses cannot hide behind increased coverage.
CONFIRMED: both complete tables join on stable IDs; the comparator explicitly
counts additions, removals, membership/role changes and protected-evidence
differences alongside classification changes. Unknown and unnamed records stay
in the comparison. Source alias selection is reported separately from membership.

H4: body readers and source recovery stay separate. CONFIRMED for this path:
the raw source helper excludes stale filename fields; previous restores retained
body readings and fingerprints; the isolated root has no acquisition/recovery
inputs; inspect_bodies=false prevents a body read. Existing native/source facts
remain available to the maintained precedence rules.
