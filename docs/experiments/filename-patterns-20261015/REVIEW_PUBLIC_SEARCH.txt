Patch summary
-------------
Search now offers Original catalog (default) and Use reviewed categories. In the
second mode, every alias of an admitted group uses its reviewed kind, family and
classification provenance. Other source fields, retention and scope keep their
existing meanings. Downloaded Parquet files retain original classifications.

The public reader consumes a 292,002-byte review file instead of the 1.27 GB
portable verification store. The exporter uses the maintained complete-bundle
verifier and exact original catalog pair. It emits complete narrative findings,
primary/component forms, page sections and evidence links; local receipt paths
are omitted. PDFs, rendered pages and text are hashed before publication.

Data flow and invariants
------------------------
- ReviewSnapshot verifies the complete baseline pair and the portable receipt
  chain before exposing fields. New viewer/export modules do not alter the pinned
  core verifier modules or admission policy.
- Public positions derive from that pair and the same filename sort used by
  publish-filename-viewer.py:138. The browser compares both original file hashes
  against source_manifest before admitting the review file.
- Original catalog fields remain in Arrow/Parquet. Reviewed fields are copies
  selected by an explicit query. No source-level filename or URL is rewritten.
- Only candidate_applied changes matching. annotation_only_unsupported_forms
  requires selected == baseline in the public reader. No new taxonomy forms.
- An archive or JSON hash mismatch refuses reviews. Original mode remains usable.
- Build staging verifies all 671 evidence objects. The browser checks the review
  JSON and its locators; ordinary PDF/image navigation relies on the staged site
  bytes rather than doing a second client-side content digest.
- Default downloads and the R2 selector stay unchanged. Public evidence is stored
  with the Pages deployment, with the small descriptor committed in source.
