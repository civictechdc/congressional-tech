The historical reviews now include all 25 Disclosure Statement repairs. Six of

The refreshed alias audit covers all 7,526 source rows and 1,949 complete groups,

Execution and safeguards
-------------------------
catalog_review_evidence.row_digest (:25) reuses the replay tool's canonical JSON
encoder and hashes the complete row. load_filename_reviews (:29) verifies the
checkpoint, review note and original ledger digests. It refuses duplicate input
or decision IDs, unknown decisions, mismatched original-row hashes and attempted
content or release approval. Only the two explicitly defined filename outcomes
are accepted: supported disclosure wording and unresolved Award List.

apply_filename_reviews (:63) runs after historical-repair linkage and before
adding filename-review annotations. It compares that complete current row with
the checkpoint's original-row digest. An ID match is insufficient. Changes to
aliases, body keys, classifications, flags or even prior review metadata prevent
inheritance and produce complete_row_changed. This conservative check can require
a new review after metadata changes; it never silently relaxes the match.
All receipts compare against the same pre-annotation row. A supported outcome
changes only a needs_review basis to filename_interpretation_review. Unresolved
outcomes remain visible without clearing pending status. No source table changes.

The existing run function rechecks all bound files and implementation bytes
before writing to a new output directory. It records unmatched and out-of-scope
decisions separately. Output summaries distinguish historical repair reviews,
filename interpretations, pending content review and release approval.

VERDICT: APPROVE this bounded evidence linkage. It strengthens review provenance
without changing production classification. It does not establish independent
content truth, population accuracy or publication readiness.
