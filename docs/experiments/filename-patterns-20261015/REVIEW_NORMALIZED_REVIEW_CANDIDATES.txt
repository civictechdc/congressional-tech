Data flow and invariants
------------------------
H1: Normalization can be recorded without weakening the original full-row binding.
Confirmed: validate_transition permits only the existing filename restoration and
document member union. It compares every other non-null value and exact identities.
Raw rows, historical receipts, proposals and earlier candidates are never modified.

H2: Rebinding could accidentally change the reviewed forms or their attribution.
Guarded: run reloads complete receipts, recovers each original from its own bound
ledger, and calls the existing selection path. Its comparison permits only the
new baseline/review group digests and the document filename claim to differ from
the previous candidate. A changed form, selected interpretation, source receipt,
review flag or other candidate field raises before output creation.

H3: The normalized pair may be reconstructed and lose nested values or metadata.
Avoided: both complete Parquet files are copied byte-for-byte from the bound disk
replay outputs and hash-checked. Full pair reference validation precedes copying.
Inputs are rechecked before and after writing; implementation identity is checked
before output creation. Failures after writing leave an incomplete directory
without a completed summary/checkpoint. Existing output directories are refused.

Next steps and conclusion
-------------------------

input: subtracting families inferred from old kinds can erase a family that also
has publisher-context support. Identify actual affected rows and preserve that
provenance through the maintained selector. Then define the explicit review input
and withdrawal behavior for production, resolve the five unsupported packet forms,
and qualify the broader catalog. Independent references and matching publication
evidence remain separate requirements; held-out body review remains locked.
