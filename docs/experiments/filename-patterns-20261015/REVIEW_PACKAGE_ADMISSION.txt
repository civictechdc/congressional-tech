Package receipt admission and separate candidate output: self-review
===================================================================
Findings
--------
No blocking findings within this local admission path. The package verifies the
existing receipt chain and compiles candidates without writing baseline indexes.
It does not independently verify the assistant's visual conclusions or make a
candidate a production selection. Local receipt paths remain a portability limit.

Data flow and invariants
------------------------
H1: Receipt validation can move without changing reviewed meaning or provenance.
Confirmed: maintained and historical readers return exactly the same 86 review
records, 530 pages and complete binding map on the actual receipt chain. Saved PDF
and render hashes remain identical; no source evidence is rewritten.
H2: Fresh group compilation can discard a packet component or silently transfer
review to changed members. Prevented by exact proposal/receipt set checks, original
row hashes, member locator equality, eligible body and body-union checks. Unsupported
forms remain whole-packet annotations through the shared selector.
H3: A candidate bundle could become an accidental baseline update.
Prevented structurally: only the new candidates.jsonl and summary.json are write
targets. The source/document pair is read and hash-checked again. A valid completed
summary marks completion; an interrupted output is not reusable and cannot be
overwritten by this command. Actual selection still returns production_selected=false.

The actual package command ran with package-only PYTHONPATH on the complete normalized

Limits and next steps
---------------------
This run qualifies the selected reviewed cohort, not every group in the full catalog.
Batching limits conversion size per batch; the selected rows and candidates remain
resident and a single large nested row can still dominate memory. The caller runs
from the directory expected by historical receipt locators. A future published
bundle must avoid leaking local paths and define portable evidence references.

Next define and test a bundle reader that verifies a pinned summary/output hash,
requires the matching baseline and rechecks each candidate's compiled group binding.
It must reject stale or altered data and support withdrawing the bundle by omitting
it. Then evaluate use against a broader catalog and resolve the five unsupported
packet forms before any viewer/publication adoption. Independent reference and
held-out/publication gates remain separate.
