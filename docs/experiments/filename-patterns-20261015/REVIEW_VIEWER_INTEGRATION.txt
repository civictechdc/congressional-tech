Local complete-document review preview: self-review
===================================================

Findings
--------
No unresolved correctness finding in the inspected patch. This is a self-review,
not an independent reference or release review. Live verification results are
recorded separately in viewer_review_checkpoint_v1.json.

Resolved during implementation: the baseline result initially shared its kind
list with the caller. ReviewSnapshot.selection now copies that value; the
mutation assertion in tests/test_document_review_viewer.py preserves the original
rows. Rendered-page ordering uses the admitted numeric page suffix, not dictionary
order, so page 10 cannot be substituted for page 2. No-review lookups avoid reading
full nested groups; configured failures remain visible before that fast path.
The real in-app browser left an inline PDF preview blank. The reviewed PDF is now
an explicit attachment download; PNG page images remain viewable directly. The
HTTP test checks that disposition, and the live checks verify the same PDF bytes.
Original archive-access failures are labeled separately from review evidence.
Concurrent browser/API requests exposed PyArrow ReadRangeCache errors on shared
ParquetFile objects. Catalog now serializes its file reads with one lock, including
advanced-field searches. The controlled overlapping-read test and concurrent HTTP
test cover the same boundary; resident Arrow list/filter operations stay unchanged.

Data flow and invariants
------------------------
Catalog bytes -> pinned ReviewSnapshot -> full current group -> maintained selector
-> separate original/preview fields plus complete body_observation -> detail panel.
Evidence type/page -> a locator from the verified observation -> closed portable
resolver -> exact returned bytes and known MIME type. No client filesystem locator. Catalog.read_lock surrounds full source/document
row-group reads and advanced search column reads; ParquetFile caches are never
used by simultaneous HTTP requests.

Original rows, search filters, download routes and saved indexes remain baseline.
The browser never mutates catalog state. Withdrawal applies to the open preview;
reopening starts a fresh preview. File changes refuse selection until restart.
Evidence is loaded from the portable store, with no original-path fallback.
Historical receipt/source locators remain literal in API data. The preview labels
assistant review and its lack of independent/reference/release approval.

  non-PNG refusal, nonexistent pages, arbitrary types and changed source rows.

- :70 covers a different baseline before admission; :77 uses the actual HTTP
  handler for selection, withdrawal, evidence, stale catalog URLs, invalid types,

- :784 distinguishes failed verification from no review. :797 confirms the shared

  test at :805 confirms a prior document cannot overwrite a new review panel.
- tests/test_document_filename_viewer.py:538 uses guarded real Parquet readers
  with competing detail/source/search requests to reject overlapping file reads.
  The HTTP review test also issues 30 concurrent entry/review requests.
- Existing viewer tests cover ordinary source/detail behavior and Host refusal;
  bundle/portable tests cover exact complete receipt, policy and catalog bindings.

Limits and next action
-----------------------
The local preview is the only newly connected consumer. Public data publication,
search using reviewed categories, independent reference review and held-out
qualification are not implemented by this patch. The full portable store is
verified server-side once; it is not downloaded by the browser. File stat checks
assume normal local immutable files, not an adversarial filesystem capable of
forging metadata. Full nested reads for reviewed groups retain the existing local
viewer row-group memory behavior; no new speed or memory improvement is claimed.

Live results: all 86 groups / 530 pages match the admitted bundle; 81 selections
and five annotations persist, with 86 successful withdrawals. Twenty-four HTTP
evidence downloads match their original hashes. Seventy-two concurrent detail and
review requests pass while the full-cohort checker also runs. The real browser
shows supported, unsupported, unaffected and verification-failure cases, restores
withdrawn kinds, displays page images and downloads the exact reviewed PDF. The
119-page unsupported packet exposes 119 page links and its complete retained notes.
133 Python tests and 41 browser interaction tests pass. Both complete baseline
files and all 11 protected evaluation inputs remain unchanged.

VERDICT: APPROVE for optional local preview.

Confidence: HIGH for tested selection/refusal paths; no public adoption claim.
