Data flow and invariants
------------------------
H1: The larger input pair changes the reviewed candidates. Refuted: admission
produces the same 86 candidate values as the earlier extracted raw subset. Whole
file hashes remain equal to their historical pins before and after execution.
The output is separate from both raw Parquet files. This proves preservation of
excluded baseline bytes, not a semantic review of every excluded document.

H2: Equal document IDs allow normalized candidates to transfer to raw rows.
Refuted: every group digest changes with restored filename claims. The comparison
pins both sets, records each digest pair and verifies all other candidate values
match. Raw bindings fail against normalized rows; normalized selections succeed.
The earlier normalized bundle and its evidence remain preserved.

H3: Selecting only 286 sources guarantees negligible memory. Refined: all ID
columns are validated, matching row groups are decoded, and the complete selected
cohort remains resident. Sources require 59 of 1,641 row groups (60,416 physical
rows); documents require 51 of 1,212 (52,224 physical rows). Full nested values
are decoded for those groups before filtering. A batch size of 32 is not a hard
memory limit and these measurements are not a capacity guarantee for a larger
review cohort or for worst-case nested rows.
