Where time and storage go

Each item should be read, written, parsed, hashed and checked once, using what storage and the engine already prove. S ≈ 1.30M status rows, B ≈ 1.04M stored files, N ≈ 3.9M capture rows.

Why the work went wrong

  • Tickets as receipts. Many were created after the work, or created and closed in one commit. Acceptance criteria restated the fix instead of testing it.
  • Measurement skipped or too small. Checks ran on 4–4,096-row fixtures against a 1.68M-row catalog, too small to show the cost being fixed. Later rewrites overrode decisions without re-measuring.
  • Tests that agree with themselves. A firewall simulator stricter than the deployed rule, mocks of guessed engine replies, a stress test that never spills, a test asserting a bug.
  • Rules kept in prose. Invariants lived in ticket text, so the Oct 20–24 refactors broke them silently.
  • Added, not replaced. "Retirements" put a new path beside the old one, so the storage code grew from 9.0k to 27.8k lines.
  • Unreliable closing notes. They cite methods, commits and hashes that don't exist; self-awarded "CS300 A+" grades did not hold up. Evidence lived in a gitignored folder and was later deleted.
  • What worked: tickets that measured first (ct-tuez, ss-wie5, ss-g9sn, ss-1txq, ct-m9td, ct-jl1m, ct-qspb).
