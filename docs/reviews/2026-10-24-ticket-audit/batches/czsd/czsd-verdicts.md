## Epic ct-czsd: what is actually left (not graded in the averages)

The epic is `in_progress`. Proposal B- (81): the structural problem (whole-table rewrites per small
update) is real and the AC are strong and testable. But the epic never measured the production cost
it set out to remove (minutes, bytes or dollars per routine run). It also committed to a heavy
architecture before checking simpler table-format or engine options. Work so far C+ (78): 19 of 20
children closed on local and fixture evidence; production unchanged five days later; hosted path
broken Oct 20-24; a merge reverted the work for about 6 hours; code size roughly tripled.

What remains:
1. **ct-2ukk production cutover** (`ct-2ukk.md` notes 2026-10-20T16:02 and 2026-10-21T07:28): live R2
   catalog and raw import with full readback, full retained-source qualification, one operational
   writer with legacy writers quiesced, guarded v6 viewer release with live review/recovery/browser
   verification, a production cost record, then removal of superseded routes.
2. **Hosted runtime:** re-pinned to docspec-rs `c949c67` on 2026-10-24. The first live Ubuntu run is not
   yet confirmed (`output/runtime-build-c949c67-20261024/linux-qualification.md`, "Not covered").
3. **Viewer compatibility risk:** the live viewer was v5 as of 2026-10-20, but main's browser is v6-only
   since `3089e771`. Either finish the v6 cutover or restore a v5 read path (see ct-ihve).
4. **Scaling defects to fix before production:** the quadratic worklist at `source_observations.py:793`;
   the per-run full `receipts/` listing at `raw_archive.py:672`.
5. The epic note "19 of 20 ... verified on main (55ba3479)" means local verification only. Hosted
   publish was failing when the note was written.
