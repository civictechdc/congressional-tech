Severity ranking of problem tickets: ct-9at7 (cancellation bound regressed and its tests deleted; the original setTimeout yields likely cost about 23 s per full-catalog scan) > ct-15wc (replacement UI dropped the formatting reuse; the original added a duplicate cache) > ct-bs70 (byte/request regression fixtures deleted) > ct-hbxu (npm and lock configuration drift; text-only workflow tests).

Cross-ticket patterns:
1. **Unmeasured static claims, measured too small.** Only ct-hfrv and ct-hbxu had concrete failure evidence. The three browser performance tickets were static claims checked on synthetic fixtures (1,001 to 4,096 sources) against a 1.68M-row catalog, so costs that scale with the catalog (timer clamping) stayed invisible.
2. **Guarantees deleted without ever being ported.** Within two to three days, 459f5ca7, 4b4a3ba0 and 3089e771 replaced the reader and the viewer UI. These bundled commits, with messages that don't mention the change, also deleted the tests that encoded these tickets' acceptance criteria. Nobody reopened the tickets or carried the criteria forward as invariants, and `browser.md` still describes v5.
3. **Hand-rolled infrastructure next to existing primitives.** `fieldTextCache` duplicates `byteCache`; the npm bootstrap duplicates Node's bundled npm or Corepack; the v5 sparse assembly duplicates hyparquet's row selection.
