## Problem tickets by severity

1. **ct-fw0m (also ct-1dsp, ct-3djs): proofs can be forged.**
   - **Problem:** since 3089e771, the positional `VerifiedFile` constructor issues process custody without hashing. Separately, `catalog_dependency_preparation.py:208-212,370-372` trusts receipt SHAs after a restart. That restore path is disabled whenever `PYTEST_CURRENT_TEST` is set (`:200,:363`), so no test can reach it.
   - **Action:** make the constructor hash, or not issue custody. Add a forgery test that goes through the constructor. Re-hash on restore.
2. **ct-1mbc: resume of older attempts is broken.**
   - **Problem:** fb9ed402 removed the historical test-path shim, and the guard test now fails on main. Separately, 932933d1 added `export-pins --publish-to-r2`, which bypasses artifact, journal and readback, and treats 412 as success without comparing bytes (`client.py:344-349`).
   - **Action:** restore the mapping, or retire the historical case and its test on purpose. Guard or remove `--publish-to-r2`.
3. **ct-9at7: the cancellation bound regressed.**
   - **Problem:** v6 yields once per leaf of up to 8192 rows or 16 MiB (RF/catalog-v6.ts:548-558), every 2048 group visits (:571), and once per leaf in matchUrls (:584-598). Its tests were deleted in 3089e771, and `browser.md:42-44` still says 512 rows.
   - **Action:** reopen the ticket and restore a wide-fixture cancellation test.
4. **ct-idhg: closed with its headline cost untouched.**
   - **Problem:** the success path still makes about 548 full-state dumps, about 62M characters and 2,193 fsyncs, and this grows with the square of the write count (`continuation.py:143-154,217-223`; `evidence/combined-comparison.json`).
   - **Action:** use an append-only log, or retire the write-ahead journal in favour of docspec-rs create-only writes, as ct-te1p planned and never did.
5. **ct-hnxb: the memory budget was never qualified on the native path.**
   - **Problem:** the hosted memory qualification covers code that is now test-only. Native C5 has no hosted full-catalog memory qualification, and the raw evidence is gone.
   - **Action:** qualify native C5 on the next hosted run.
6. **ct-8uwj / ct-d8z3: the measurement describes code that never landed.**
   - **Problem:** the measured candidate f5257491 is not on main. Before the merge, 744edd6 changed 55 files (+10,972 lines) with no re-measurement. The 7-filename fixture could not see the scale regressions found that evening.
   - **Action:** annotate the report; re-measure only if efficiency claims are relied on.
7. **ct-fcxg / ct-hm4b: defaults point at a retired origin.**
   - **Problem:** `pipeline_status.py:297` and `constants.py:6` default to the retired workers.dev Worker. The reader uses `congressional-data.spicygov.ai` (RF/publication.ts:2).
   - **Action:** update the defaults.
8. **ct-15wc / ct-bs70: criteria were not carried into the replacements.**
   - **Problem:** the acceptance criteria were not ported. The replacement detail UI runs JSON.stringify on every keystroke, and the byte/request regression fixtures were deleted.
   - **Action:** small follow-ups.
9. **ct-hbxu: configuration drift.**
   - **Problem:** npm pin drift (root 11.0.0 vs site 11.19.1), `.gitignore:373` still ignores locks, and there is no `engines` field.
   - **Action:** low-priority cleanup.
10. **ct-4r1c: unlocated errors and a weak test.**
    - **Problem:** some malformed event shapes raise a bare AttributeError (`admission.py:218-223`), and the rejection test accepts any ValueError.
    - **Action:** tighten the shape checks and assert messages.

## Patterns across the batch

- **Assumed problems, measured too small.**
  - Only ct-idhg cites a measurement. ct-hfrv, ct-hbxu, ct-d2lk, ct-gesp and ct-eauq name concrete defects found by tracing the code. The rest restate findings from a static audit of graded functions.
  - Verification used 7–4,096-row fixtures against a 1.68M-row catalog.
  - The full job was never profiled first, though preparation took 8,924 of 9,732 hosted seconds.
  - Net result on the fixture: fresh publication was 7.5% *slower*.
- **Acceptance criteria restate the mechanism.** Criteria such as "reuse only process-local proof…", "count one validation" and "enforce N limits" let each ticket close by implementing itself.
- **Bespoke trust machinery.** Four process-local proof registries were built to skip re-hashing: `VerifiedFile._issued`, the inventory registry, `GuardedPublicationClient._receipts` and `Continuation._reconciled`. One later refactor opened a forgery hole in the shared base.
- **Wrong order.** The tickets hardened Python/SQLite staging and a hand-rolled write-ahead journal while a docspec-rs migration plan (ff21142f) and create-only remote writes already existed. Within 3 days, native C5 (55ba3479) made ct-3djs, ct-gubr and most of ct-hnxb test-only or dormant. Only the correctness fixes (ct-gesp, ct-d2lk, ct-hfrv) survived intact.
- **Guarantees deleted without porting.** Bundled refactors (459f5ca7, 4b4a3ba0, 3089e771) deleted the tests that encoded the acceptance criteria (ct-9at7, ct-bs70, ct-15wc). No ticket was reopened, and the docs still describe v5.
