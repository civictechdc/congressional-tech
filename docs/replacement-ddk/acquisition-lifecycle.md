## Identity, occurrence and content

Equal body bytes can share storage without merging acquisitions. A receipt identifies a source occurrence; its capture index and pointer identify a body within that occurrence, including prior attempts and archive members (`receipt_writer.py:113-120,138-178,247-262`; `captures.py:41-49`). Literal requested/final/context URLs remain evidence even when normalized URL keys suppress duplicate requests (`capture_scheduler.py:435-437,518-535,598-602,855-860`). `body_sha` plus parser/version identifies a reading, not the source occurrence (`readings.py:27`; `reading_versions.py:1-9`). Publication identity additionally names the complete result and its input evidence (`archive_publish.py:421-440`).

Saved JSON objects, saved text, exact transport bytes and retained imports have different fidelity. `ReceiptWriter` names `exact-bytes`, `saved-text`, `saved-record` and `retained-file`; retained imports require recovery evidence and record `publisher_requested=False` (`receipt_writer.py:101-124`). YouTube SDK items and yt-dlp metadata are saved representations, not asserted raw HTTP responses (`youtube_event_fetcher.py:28-29,144-160`; `youtube_api/captions/main.py:97-109`). News captures carry caller-provided payload URI/hash and rights; adapter validation does not prove the caller stored that URI (`news_lake/adapters/common.py:57-97`).

## Refusal, empty, pending, correction and deletion semantics

* A successful HTTP code alone does not establish a document: `202`, zero-length bodies and incomplete `206` ranges fail the shared document rule. `429`, `503` or `Retry-After` yield retry-later; transfer failures and size limits remain distinct (`receipt_writer.py:39-53`; `receipt_metadata.py:47-87`). A provider account error is not publisher `403` or a missing source (`fetcher.py:75-92`).
* URL capture dispositions are `eligible`, `satisfied` and `excluded`. A satisfied or excluded key suppresses requests, while an eligible stored wrapper may still require a better candidate. These decisions do not delete prior bytes (`capture_scheduler.py:503-539,558-589,611-634`).
* Missing bytes, changed custody, ambiguous gzip or transient read errors remain pending. A durable unreadable decision is tied to parser/version and can be superseded; it is not a universal statement that the source is absent (`readings.py:114-156,636-687,730-736`; `_record_producer.py:590-609,724-749`).
* Keep absent, empty and unrecognized record fields distinct. Latest-source selection and parser pins determine which fact is current; historical occurrences remain retained. `current_inline_lines` ranks Congress inline records by update date then witness count; this ranking itself needs raw comparison during migration, especially true removals or shrinking replacements (`_record_producer.py:552-587`; `model/sql/selected-records.sql:1-12`).
* A failed caption fetch cannot establish no captions. Negative findings need a real observation time and scope; prior successful evidence survives later failures (`youtube_api/captions/main.py:51-74,89-109`; `test_source_observation_interpretation.py:37-84`). A forced YouTube scan retains old captures; missing playlist entries do not constitute deletion (`youtube_event_fetcher.py:200-260`).
* Raw storage is create-only. Correction changes exact indexed facts only after measured evidence and unchanged-field comparisons; restoration creates only an absent physical key from exact stored bytes (`body_store.py:38-47`; `raw_repair.py:28-175`). Derived table purge protects every kept table UUID/pin and never deletes raw (`maintenance.py:168-195`).
* Retired public link keys retain a successor when supported by prior primary/sibling identity or exact address plus matching text fingerprint; otherwise they retain removal/version information. Absence from a partial source listing is not implemented here as raw deletion (`model/sql/retired-links.sql:1-61`).
* News preserves provider discovery observations independently of shared item identity; late older upserts union evidence and retain newer scalar claims. Publication availability and cursor activation follow validation, and retired releases become unreadable through the control store (`news_lake/adapters/common.py:25-32`; `storage/coordinator.py:60-92`; `storage/docspec/lake.py:639-769`; `storage/releases.py:368-370`). Live acquisition, raw-payload deletion and any source-retraction policy remain unresolved requirements.
* Inflation skips unavailable sources and rebuilds the output from surviving frames. Missing one source can remove its prior output column. This is current observable behavior and needs an explicit replacement freshness/correction decision; it is not proof that the omitted provider removed its observations (`fetch-inflation-sources.py:126-175`).
