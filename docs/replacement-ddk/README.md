# Congressional-tech DDK replacement

The greenfield migration is in progress. The current source requires one public
DDK catalog across MCP, API, browser, comparison and publication consumers.
The old schema generator, reverse converter and legacy reader decoder are removed.
Production migration remains incomplete: the retained application producer,
original source admission, acquisition and nonarchive callers still need native
qualification and adoption.

DDK owns dataset definitions, relationships and generated checks. Application
code owns domain interpretation. DocSpec owns the job's execution, retained
results, acceptance and selection. The application publisher keeps its existing
conditional activation authority. The new composition adds no application phase
journal, retry controller or mutable selection, and it delivers native exports
from their retained paths through an explicit file inventory.

The retained release path captures the exact small definition and profile files,
prepares the complete native job, binds required reports to the actual schema,
and calls native prepare and accept. It retains the first accepted receipt for
DDK schema and rule checking. After controls finalize separately from data, it
requests selection of that exact checked candidate. Pending, unknown and failed
observations preserve their evidence and produce no selected release. Independent
red/green source reviews found no remaining concrete issue in the scoped recovery,
path-separation and incomplete-observation fixes. The preserved small fixture now
passes native acceptance, DDK qualification and selection after a policy-only
schema repair. Its original exports were reused without computation. The source22
development runtime also passed the current rich fixture on its first fresh
attempt at the original limits. Final runtime qualification and production input
admission remain separate.

The model entry verifies mandatory runtime pins, retains local input paths through
uncertain admission, and resumes only the original request and digest. Both new
and resumed model requests require original producer prerequisites. The old model
phase journal and daily checkpoint import are removed. Nightly publication no
longer classifies or deletes candidates using those journals. External activation
refuses before effects until native frozen publication intent is supported.

These are focused results, not a full Python lane, product release or production
cutover. Durable receipts are under the main checkout's
`.cache/archive-release/ddk-replacement-20261106/`; [status](status.json) records
exact scopes and earlier results. No execution speedup is claimed. The concrete
simplification is one definition/check path and removal of duplicate schema
machinery and export copying.
