Compiled document review input
==============================

The maintained selection API is congress_api.retention.document_reviews.
It applies a previously verified body review to a fresh grouped baseline and
returns a separate candidate. Ordinary catalog grouping and refresh do not call
it automatically. The existing experiment now calls this implementation; there
is one selection and digest implementation for both package and experiment use.

Ownership
---------
house_naming owns lexical filename interpretation and kind-to-family mappings.
congress_api.retention owns retained body/source evidence, grouping and selection.
A body review is evidence about captured bytes, not a new filename rule.
document_review_receipts verifies local receipt chains and compiles this input.
document_review_catalog admits a pinned proposal/receipt pair against complete
current groups and writes a separate candidate bundle. The historical experiment
reader remains unchanged because earlier receipts bind its source hash; it is not
a package dependency. Current candidate experiments use the maintained reader.

What goes in
------------
review_group_digest(document, sources) receives the complete baseline document and
every source member after grouping/refresh. It binds all semantic values, sorting
members by source_id and dictionary keys. It ignores null dictionary padding only;
list order, null list entries, duplicate values, source text and nested evidence
remain significant. Duplicate members, foreign document IDs and a prior review
candidate used as a baseline raise ValueError.

apply_review_candidate(document, sources, review=None) receives that same baseline.
The optional compiled review is the existing dictionary shape:

Field | Meaning
document_id | Exact grouped document identity.
group_sha256 | Digest of the complete normalized baseline and all source members.
original_row_sha256 | Exact original review-selection row, checked during compilation.
receipt, receipt_sha256 | Locator and verified hash of the complete review receipt.
body_key, body_sha256 | Retained body locator and verified decoded-byte digest.
observed_forms | Distinct document forms observed across the complete body.
primary_forms, component_forms | Reviewed packet roles; their union equals observed_forms.
reviewer | assistant for the current admitted review input.
independent_reference, release_approved | Explicit false; selection does not establish either.

Compiler obligations
--------------------
Before calling the selector with a review, the caller must verify the complete
receipt chain and its source-row bindings, decoded body bytes, PDF signature/page
count, all-page coverage and retained evidence hashes. It must compare the proposed
forms with that review and verify exact original/current membership and body
identity. The current group must have document role and exactly the reviewed
eligible body, while its retained body union may also include old failed captures.
The package implements these checks in document_review_receipts.load_reviews and
compile_review, called by document_review_catalog.write_candidates. The selection
API itself reads no receipt or body files; digest equality alone does not establish
review correctness or page coverage. Receipt validation checks recorded all-page
coverage and evidence hashes; it does not independently repeat a visual review.

What happens and what comes out
-------------------------------
The selector copies the baseline before choosing a result. No supplied review
returns no_review and the unchanged baseline. A different document ID or group
digest returns scope_changed and the unchanged baseline. Unsupported forms keep
the whole packet as annotation_only_unsupported_forms; the selector does not apply
the supported subset. Invalid assistant flags or inconsistent form sets raise
ValueError. These checks do not replace the compiler obligations above.

A supported exact binding returns candidate_applied. It changes only selected
document_kind, document_kind_source and document_family. Filename claims, native
content readings and source context remain intact. Provenance is explicitly
assistant_complete_body_review. Context-supported nomination families survive a
change in reviewed form through the maintained paired-source predicate.

The returned dictionary contains status, baseline_group_sha256, document and a
detached copy of review. production_selected, independent_reference and
release_approved remain false. Callers keep the original baseline separately and
must not write the candidate back as baseline cache input. To withdraw, call with
the original current baseline and no review. To correct, verify and compile the
replacement receipt against that baseline; do not mutate the previous candidate.

How we check it
---------------
Package tests exercise digest semantics, optional/default behavior, complete packet
refusal, malformed compiled inputs, detached outputs and invalid cache reuse.
Experiment tests exercise original receipt compilation and publisher context.
The complete 86-group / 286-source cohort is replayed through seven grouping and
refresh scenarios against its saved candidates to prove extraction compatibility.
Import-fence tests keep retained-data code inside its package responsibility.

Optional local command
----------------------
Run from the directory relative to which the historical receipt paths were saved:

python -m congress_api.retention.document_review_catalog \
  --sources PATH/TO/document-filenames.parquet \
  --documents PATH/TO/documents.parquet \
  --proposals PATH/TO/proposals.json --proposals-sha256 EXPECTED_PROPOSAL_HASH \
  --receipt PATH/TO/latest-receipt.json --receipt-sha256 EXPECTED_RECEIPT_HASH \
  --output NEW_OUTPUT_DIRECTORY

Use hashes from the pinned evidence, not a hash recomputed after an unexpected
change. Install the package's archive extras for Parquet/catalog support. Proposal
records and the receipt chain must cover exactly the same reviewed group IDs.
The command validates the whole pair's references, then reads complete selected
groups with ID scans and batches of 32. This bounds batch expansion, not the total
size of the selected cohort or any single nested row.

The new directory contains candidates.jsonl and summary.json. Candidate records
include their compiled reviews; the summary binds source files, receipts, evidence,
implementation and output bytes. The summary is the completion marker. Interrupted
or failed outputs without a completed summary are not reusable, and existing output
directories are refused. Inputs are hash-checked again before and after writing.
Catalog indexes and publication selectors are never write targets.

Remaining integration work
--------------------------
The explicit package command is now available; recurring catalog capture does not
invoke it automatically. Before consuming its output in the viewer or publication,
define how a reader verifies a bundle against its current baseline and rejects stale
bindings while retaining annotations. Historical paths are local and must not be
presented as a portable publication format. Independent references, the five
unsupported packet forms, full-catalog execution and publication remain separate
decisions. No source-body acquisition, held-out evaluation, automatic selection or
release permission is introduced by this API.
