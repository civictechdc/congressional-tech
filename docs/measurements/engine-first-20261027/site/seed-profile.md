# v5 seed conversion: bounded SQL measurements

Pinned oracle: catalog `469ef1ebf6864739a2c8a4c096defcc0`, generation `596f08fa2dbf4875bb8da7dc94e33847`, 1,241,157 documents. Runtime: immutable `engine-885e8c3`, four CPUs, 14 GiB pool, 3 GiB spill; the maintained local monitor enforces 16 GiB physical memory. These are local observations, not production capacity guarantees.

The first three full attempts refused at `seed_docs` (44.464 s), `seed_source_status` (88.771 s), and `seed_presented` (117.139 s). Narrow hash-build inputs and releasing finished relations let the fourth attempt write all public Parquets and private identity proofs. That attempt timed out at its 600-second forecast bound: 8,087,838,496 B sampled physical memory, no completed native result or accepted manifest. Its files remain unqualified.

The approved no-export diagnostic ran the current conversion steps once and analyzed each final query separately: 240.267 s native job wall time, 241.577 s monitored, 7,851,941,592 B sampled physical memory. The 16 final queries took approximately 25 seconds altogether. The slowest was `seed_invariants` at 10.407 s. Its hottest operator was a final partitioned aggregate over legacy document IDs: 5.08 s summed compute, 2.48 million emitted rows including spill processing, 12 spills / 90.3 MB, four partitions. Body-key validation consumed 3.86 s over 1.66 million rows. These results do not identify the fourth attempt's final delay; no isolated full-scale speedup is claimed for the MIN/MAX collision witness.

An exact native count under the earlier mapping found 89,611 exclusions (7.22%), including 66,234 documents without admitted sources. Every one already had a resolved document filename and a named source for the same body at a different URL. Lead amendment 2 permits that document's filename for a missing source filename only when the source has that same body. Revised counts are 3,532 missing filenames plus 19,845 missing formats: 23,377 documents (1.883%), below the approved 3% stop. The rule supplies 95,298 physical source filenames; it also affects sources of already admitted documents. The source URL and canonical ID formulas remain unchanged.

On the actual 50-document sample, the new rule admits one additional document and changes another document's source membership. All 48 documents whose canonical document ID and source membership stay unchanged retain equal list/detail field digests. Global range starts are excluded because earlier inserted rows shift offsets; empty alternate lists are checked separately. All joins, grouping and comparison run in native SQL. Before the rule change, all 12 public files and the manifest remained byte-identical through the performance changes.

A separate diagnostic found that `SELECT DISTINCT o.document_id` over a joined equality of source-ID lists returns one row where the equivalent flat join returns 48. The physical plan adds `fetch=1`. Core owns this native defect; no application workaround was added. The lead explicitly authorized the next full attempt with exact document and source reconciliation required and the qualified 2,700-second runtime bound. Memory, spill, scratch, and data guards remain unchanged. Every `DISTINCT` occurrence in the actual seed/shared-writer job is retained in the private `seed/full-v5/distinct-inventory.json` for comparison with core's trigger condition.

Evidence: owned `codex-site/seed/full-v4/query-profiles/all-current/`, `revised-counts/`, `source-name-unaffected-proof-v2/`, and monitor records. Full release and browser qualification remain separate gates.
