# C5: known-file upload

The largest converted F0 file is `detail.parquet`, 48,923,028 bytes. The native
transfer fixture retains its 8,388,625-byte case and adds a 50,331,665-byte case.
Each sends one create-only PUT with `Content-MD5`, preserves exact bytes and
sends no HEAD, GET or multipart request. Cancellation and capacity refusal have
separate passing fixtures. Application release identity remains outside Rust.

A warm run through Cargo's native `/usr/bin/time -l` runner measured maximum
resident memory of **215,089,152 bytes** and peak memory footprint of
190,284,520 bytes. This includes the loopback provider and test input copies;
the larger case configures a 256 MiB engine budget. The file buffer fits, so
BIND's rule does not require a file-backed single-PUT implementation.

Evidence: engine transfer contracts `20454f9`, cancellation `4232caa`/`4aa75aa`,
binding `c394517`, and the later largest-file fixture. Root scratch retains
`cx_c5_largest_memory.log`. Code and architecture reviews approve the transfer
service. This local macOS check establishes request counts and this transfer's
memory use; whole-model and Linux/Basin acceptance remain separate.
