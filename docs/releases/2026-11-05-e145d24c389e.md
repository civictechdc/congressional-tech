## Changes for archive users

- **More source material and clearer provenance.** Added 1,128 documents, original copies for 188 recovered documents, 13 meeting transcript links, six recordings and one nomination. Another 164,601 source entries now identify the page that listed the document. URL-attempt history includes the retained October 30–31 receipts.
- **Witness links survive re-fetches.** Published historical-to-current witness mappings and site redirects. All 35,899 witness keys removed from the previous release resolve to their supported successors. Ambiguous and unresolved mappings remain explicit; names alone never establish identity. This does not restore pre-occurrence-v2 links from `c94bfedc` and earlier.
- **Recordings survive incomplete API responses.** A re-fetch with the same update timestamp no longer erases collections it omits. The eight affected meetings retain their videos, recording matches and coverage. Explicit empty values and genuinely later updates still take effect.
- **Document facts survive a saved-copy change.** Package IDs, filename dates and Congress now use evidence across identical copies. Invalid filename-derived GovInfo IDs are rejected. Eight conflicting bill identities leave the package field empty while preserving their source claims; seven same-bill version choices remain intact.
- **Dates have clearer evidence.** Act-title years no longer become document dates. The EPS Improvement Act opening statement retains January 12, 2016, and `CHRG-117hhrg49353` uses its June 23, 2022 hearing date instead of a 2023 reposting date. The release exposes accepted, suspect and undated classifications and describes coverage bounds as observed dates, not complete historical coverage.
- **Coverage and recovery descriptions are more accurate.** Roster coverage reflects the Congresses actually published. Removed pipeline boilerplate from 10,772 recovery identity notes; an empty explanation no longer masquerades as an identity finding.

## Pipeline and operations

- **Nightly publication is restored at 05:30 local time.** Receipt discovery, backlog budgeting and body-custody checks run before captures advance. Backfills record producer lineage; incomplete daily work returns a failure. Bounded read retries handle transient storage errors. The scheduled fetch uses HTTPS, with the existing SSH push route preserved.
- **Native processing uses less repeated work.** Staged witness aggregation and distinct-key counts, reduced repeated URL parsing, and replaced the final package-selection query's unbounded window. The final full model peaked at 9.981 GiB under its 14 GiB watchdog limit.
- **Parser repair stayed selective.** Recomputed 295 of 1,403,275 filename readings. Reconciled the related House XML parser version while preserving all 42,551 meeting values without replaying XML payloads. Imported both generations, verified parity and updated the scheduled jobs' producer anchors.
- **Maintenance completed.** Verified 307,033 bodies with zero content or identity failures, stored the verification history, and removed 74 unreferenced derived objects totaling about 290 MB. Raw bodies and protected releases were preserved. Maintenance now uses bounded concurrent readers, reusable verification history, read-only planning and a 10 GiB runaway limit based on its measured 5.989 GiB peak. The 33 capture-digest repair candidates remain evidence only.
- **Project guidance is consolidated.** Included the user-persona questions and date-source experiments as research records, plus the active coordinated plan for remaining repairs. Corrected the filename-parser ownership note and excluded machine-specific OpenCode configuration from Git.

Release cleanup closed ten delivered release and maintenance tickets and removed 24 merged worktrees. Historical ticket records, recovery refs and unique evidence were preserved; unresolved work stays active.
