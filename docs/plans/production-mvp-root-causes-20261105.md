# Production MVP: root causes across 15 tickets

The strongest common thread is loss of source meaning as records move through extraction, modeling and reading. Some relationships are asked to prove more than they establish; some supplied facts are flattened away; and several readers treat missing or failed supporting data as absence of the main record. These mechanisms explain much of the backlog without requiring a new engine or a general pipeline rewrite.

The same three reviewers applied the ETL workflow to five tickets each, following the actual consumer backward to current code and retained source/derived rows. The scope is the seven MVP items and the next eight in the [priority plan](production-mvp-priorities-20261105.md). The audit used the retained `e145d24c389e` release and current source; the recorded baseline is `33d2d319`. Detailed traces distinguish observed values, source-level mechanisms and remaining hypotheses.

The audit initially left the tickets unchanged. The authorized follow-up on November 5 incorporated these findings into all 15 active ticket descriptions, preserving their metadata and historical notes. The tickets remain separate. `ct-t915` owns the shared recording-display and older-schema browser check; `ct-j78x` references that result and retains its model, coverage and MCP checks.

## What the audit changed

1. **The three 1901 cases are alias qualification errors, not proven stale filename readings.** The displayed-name readings already return no date. Alternate names such as `transcript-02271901` supply a date with `filename_date_valid=false`; the model treats it as plausible because it predates capture and has no Congress bound. Publication then labels it accepted. Replaying the same reading is not the causal repair. Preserve the alias as evidence and qualify its date meaning before using it.
2. **The three printed-cover disagreements are not evidence of one broken meeting parser.** One document is attached to both June and September meetings, and `MIN(meeting_date)` selects June although the vetted print relation supports September. The other two prints are explicitly attached by publisher records to meetings whose dates differ from their covers. Preserve the attachments and distinguish their context from evidence of the print's date. Do not rewrite the meeting dates merely to make the print agree.
3. **The current JEC defect spans parsing and matching.** One witness's title/employer continues across adjacent paragraphs sharing a testimony link; the parser creates an extra witness from the continuation. Separately, the exact page matches event `335901` by date/title but its committee mapping and null-chamber filter exclude that event. Both `jjec00` and `jsec00` exist in the reference table, so globally renaming a code or matching by committee name alone would be unsafe.
4. **The old three-layout diagnosis is incomplete.** The JEC mechanisms above are demonstrated on retained raw, parsed and published rows. The historical Intelligence and Environment counts do not establish their present causes; inspect one retained missing relationship per host before choosing their repair. The old claim about a dependency on `retention/document_links.py` is also stale; the witness-helper version omission is the current dependency finding.
5. **Caption correctness needs two rules and delivery wiring.** Excluding playlist segments does not resolve duplicate `caption`/`live` labels. Making labels exclusive does not make a segment a complete track. Both producer decisions need their own checks, followed by the existing publication path.

## Work that can be shared

1. **Ship the site resilience/current-witness correction and the PDF dependency patch independently.** They can use existing archive data. A PDF runtime patch should not move archive parser pins or trigger a corpus replay.
2. **Coordinate the semantic model changes through one integration owner.** Witness scope, print dates, alias dates, recording association and nomination activities can reuse held inputs. Each keeps its own meaning and regression cases. Publish ready changes together where practical, without making every diagnosis a prerequisite for every other fix.
3. **Treat JEC matching, chamber missingness and witness parsing as a connected source-to-reader repair.** The alias and chamber exclusions can be repaired with existing derived inputs. The false-person parser fix has a separate replay scope. Coordinate shared witness-helper semantics with the MODS affiliation work so parser versions remain honest.
4. **Carry source attributes and finish already available data separately from reacquisition.** Congress.gov document metadata needs targeted replay because it was discarded before the typed input table. Rules XML needs admission, not re-fetching. Nomination activity needs a model change, not a parser run. Caption work needs both integrity decisions and complete wiring.
5. **Keep recovery and ambiguous identity work bounded.** Reuse completed recovery scopes, repair the demonstrated oversized request mechanism, and inspect the exact unresolved identity. Do not turn transport errors into empty results or unknown bill types into guessed IDs.

These are coordination packages, not proposed ticket mergers. Source parsing, relation meaning, capture admission and runtime behavior have different owners and tests. A single shared release can reduce repeated work, but it does not prove the fixes have one cause.
