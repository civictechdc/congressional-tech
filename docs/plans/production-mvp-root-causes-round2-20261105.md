# Production MVP: root causes across the next 15 tickets

This round covers original ranks 16–30 in the 52-ticket MVP ranking. The [current priority plan](production-mvp-priorities-20261105.md) was renumbered after the five HTML stage tickets were absorbed into `ct-082q`; the audit below preserves its original ticket IDs and ranks. The main pattern is a gap between work that exists and the path that actually delivers it: extraction code remains on a branch, acquisition fixes target an unused caller, comparisons use old fields or overly broad identities, and scheduled publication does not retain the completed work needed for recovery.

The most important new user-facing finding is a witness occurrence that is incorrectly hidden by precedence. The nightly ticket also contains concrete approval and recovery defects. Several other tickets describe stages of one unfinished feature or migration rather than independent product defects.

Three GPT-6.1 Sol/xhigh reviewers applied the greybeard and ETL workflow skills to five tickets each. Source baseline: `c3ee2eec`. The audit used retained release `e145d24c389e`, bounded local queries and selected live read-only checks on November 5. Hosted MCP reports software **0.6.1** and selects that release. No implementation, ticket edits, replay, acquisition, deployment or application tests were performed.

## Findings that change the earlier plan

### 1. Witness preservation includes an actual visibility bug

The historical comparison's **19,475** count is the number of event/normalized-name groups. The three hash-matched old CSVs contain 36,301 input rows, 31,185 event/name/source/origin combinations, and 31,195 combinations when position and organization are also retained. Those are different accounting units, not counts of missing people. There are 2,975 event/name groups with differing position or organization.

One concrete case proves why the distinction matters. For event **100520**, the same retained House witness XML lists **W. Ron Allen twice**, with different positions, organizations, biographies and statements. Both entries are active and have the same addition/publication timestamps. The second is not a later correction to the first. Published e145 retains both rows, but marks the United States Commissioner/Pacific Salmon Commissioner occurrence `2a0208241fb6a49d` as superseded by the Tribal Council Chairman/CEO occurrence `db779668e63d56bb`.

`model/sql/witness-precedence.sql:25–33` treats an earlier same-record occurrence with a matching name as the preferred occurrence, without requiring the roles or document evidence to agree. XML order is being used as proof of equivalence. This is a producer precedence defect; changing the parser or merely producing a more detailed migration report would not repair it.

**Plan correction:** bring this narrow part of `ct-x78c` into the first witness work. The `ct-t915` default-list correction must preserve these distinct roles, statements and keys while hiding genuine superseded duplicates. Applying `superseded_by IS NULL` alone would carry this defect into the site; the existing MCP default already applies that filter. Reuse the held XML and published rows for a model-only correction and both-reader checks.

### 2. The nightly ticket is more than an unobserved scheduled run

The restored 05:30 local job is loaded and had zero invocations since restoration when inspected. That observation alone does not diagnose a failure. Two separate source-level defects do:

- `release_comparison.py:533–547` emits an unverified `url_state.parquet | added URLs | new attempts` group for a newly attempted URL. `release_gate.py:238–271` excludes that group from automatic approval. A new document can therefore satisfy the raw-receipt rule and still be refused because its dependent URL state is outside the allowed categories. The positive fixture omits URL state. This exact additions-only scenario was traced in code, not executed in this audit; the historical refused run also contained real changes and removals.
- `nightly_publish.py:97–105,125–165` saves small JSON evidence, then removes ignored output at the next run. The worktree actually holds a completed-model checkpoint, release files and a 7.3 MB result above the evidence-copy limit. The normal job does not resume them. The existing controller can reuse exact completed work, as the approved e145 recovery demonstrated, but the scheduled wrapper does not connect to it. Authoritative R2/Basin tables and the separately retained approved handoff are outside this cleanup.

**Plan correction:** treat `ct-ud0b` as functional freshness and recovery work when unattended updates are promised. The minimal automatic rule covers qualifying new documents and their attributable dependent rows. It must not approve unrelated entity additions merely because their counts are positive. Keep one reusable completed candidate through its final consumer; reuse the existing controller and pointer protections.

### 3. The House repair must reach the current capture path

The old `acquisition/house.py:lacking()` decision treats ordinary documents plus a transcript as sufficient, overlooking structured committee records. But the maintained Mac publication path ingests receipts, and the configured capture path queues release URLs, seeds and discovery results. Neither calls that old House gap-filler. Editing it alone would not fix the production flow.

The selected e145 data still has the historical **295/49 coverage signature**: amendment-document events without committee records, split by whether `house_xml_updated` is absent or present. That field is not itself a complete capture inventory. Trace the 49 separately; do not assume they need a fetch. Event `118300` already has an exact held later capture and 31 parsed records, so it needs input admission and publication rather than reacquisition. The hosted capture workflow was disabled manually at inspection; code wiring and schedule activity are separate facts.

### 4. Much of the meeting-field discrepancy is in the comparator

The existing SpicyRegs comparator still lists Congress, update date, room and building as missing destinations, although e145 publishes them. It compares the mixed `meeting_type` instead of `congress_gov_meeting_type`.

A bounded comparison of retained SpicyRegs `37a6ebd4` with e145 matched 6,091 events. Using the equivalent Congress.gov field reduced House type differences from **1,386 to one**, event `119583`, which also lacks the native Congress and update values. Six update differences, one Congress difference, two first-start differences, 31 first-building differences and 18 first-room differences remain for interpretation. Of the location differences, 30 building and 17 room values are supplied only by the archive. These are field comparisons, not a demonstrated defect count: other examples include an upstream room placeholder, leading whitespace and different source update times. First-sitting comparisons also need care where an event has several sittings.

**Plan correction:** update the comparison's mappings and inspect those residuals. Reuse the delivered time/location parser and retained raw checks. Do not restart a parser backfill to satisfy stale missing-column claims.

### 5. HTML delivery can exclude an unrelated identity change

The retained e145 physical schemas contain none of the six proposed HTML detail fields. Four useful commits remain on `r2-html`: selection `a5a1d696`, producer `ea3ac1b4`, daily wiring `e38a32af`, and native publication `e9137fe3`. The branch itself still lacks the active `html_metadata` pin and a configured job enabling the derived stage. Field names or isolated fixtures would not establish populated production output.

Port those scoped changes onto current code. Leave fingerprint commit `7c00e6fa` for its separate identity decision: it changes deduplication and shared parser dependencies. Initial metadata extraction should cover eligible missing body/parser/version pairs; it does not require replaying accepted sniff, HTML, XML and JSON readings. Reconcile the changed orchestration bundle and target catalog before enabling the daily stage.

Use the current stored inputs to measure the actual work set. The older 192,191-body plan is not a current population count. Keep descriptions and previews compact, preserve each fact's capture context, and make the exact selected source and text accessible on demand. A branch case where an empty block precedes a short selected block can attach the wrong snippet; resolve it within the selector work. Large metadata arrays exceeding MCP's summary limit are a conditional risk to measure, not an observed production regression.

## Practical sequence

1. **Add the confirmed witness occurrence to the first-round witness repair.** It changes a current answer and shares the existing model and reader work. A new migration report alone would miss the user-visible defect.
2. **Repair nightly behavior if the product promises ongoing updates.** Use a small native-shaped new-document/URL case and a completed-stage interruption to qualify the two mechanisms. A frozen, honestly dated research release remains useful while this work is open.
3. **Deliver HTML as one bounded product increment.** Integrate extraction, native fields and the two readers around a small retained source set; expand the replay only from the measured missing-pair list. Keep fingerprint identity changes separate.
4. **Finish missing-input and field comparisons at their actual owners.** The eight meeting IDs need receipt/admission traces; House acquisition needs the current entry point; historical rosters need upstream history; meeting-field parity needs corrected comparison mappings. These do not share one parser fix.
5. **Finish the actual consumer switch and narrow retirement.** Native publication and hosted MCP are already delivered. Preserve unresolved legacy facts, switch the dashboard, verify its selected release, then remove obsolete staging. Do not turn full migration accounting into a prerequisite for every independent feature repair.

The connection to the first round is strongest at meaning and occurrence scope: person identity does not establish interchangeable appearances, a field with a similar name is not necessarily equivalent, and a stored body or implemented branch is not necessarily selected production data. The additional lifecycle finding is that reusable work must survive until its last real consumer, including an interrupted publication.
