Decision: Measure a small Rust reqwest implementation on the six URLs already timed through Python.
Hypothesis: A pooled asynchronous client may reduce request overhead; network and provider variability may dominate.
Arms: Rust reqwest 0.13.5 release build; prior Python measurements are a historical reference, not a contemporaneous controlled language comparison.
Cases: Exact six URLs from raw-fetch-timing-20261001. Keep the header-only caption and GovInfo HTML error page; do not replace failures with easier sources.
Held constant: URLs, three repetitions per transport, eight concurrent slots, direct User-Agent, Zyte JSON request shape, decoded 64 MiB limit. At most 18 Zyte and 18 direct requests. No R2 writes or source crawling.
Differences: Rust reuses one shared connection pool across repetitions, permits HTTP/2, and omits Python host pacing. Rust adds a 120-second total deadline. It measures network/body decoding/hash, without the production Pydantic validation, link inspection, archival writes, or catalog rebuild. These form a combined benchmark implementation, not an isolated language change.
Evidence: Keep response bytes, status, final URL, media type, checksum, protocol, per-file durations, batch durations, and failures. Validate saved bodies using existing Python inspection code after timing.
Decision rule: Report medians and ranges for the selected inputs. Do not infer a general speedup or full-backlog completion time from six URLs or from comparison with earlier uncontrolled network observations. No production adoption.

Result: Completed 36 requests in the release build. Direct per-case medians ranged from 0.024 to 0.237 seconds; Zyte medians ranged from 0.457 to 1.564 seconds, with one caption request taking 10.595 seconds. All responses completed with HTTP 200. Existing Python inspection classified 24 as saved and 12 as html, including the known GovInfo error page. All body sizes and checksums verified; the five stable sources matched the earlier Python bodies. Direct first-batch timings were 0.307-0.404 seconds, so connection warmth matters substantially. No isolated language-speedup conclusion follows from this experiment. Source, manifest, and lockfile remain local and uncommitted. Validation: release build, cargo fmt --check, and cargo clippy --release --locked -- -D warnings passed. Evidence: .cache/reqwest-fetch-timing-20261001/summary.json and retained response bodies.
