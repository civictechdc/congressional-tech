# news-lake

Political news lake: the record **contract** (slice 1), the **Iceberg storage boundary** (slice 2), the **offline adapter/identity/analysis cores** (slices 3–6) from the design packet at [`../news-lake/docs/packet.md`](../news-lake/docs/packet.md). The docs directory is the proposed contract authority (see [`docs/adr/news-lake-contract.md`](../../docs/adr/news-lake-contract.md)) and is treated as read-only; a test keeps the shipped schema copy byte-identical to `docs/schema/news-lake.schema.json`.

## What is implemented

### Slice 1 — contract (`src/news_lake/contract/`)

- `records.py` — JSONL loading that rejects `NaN`/`Infinity` (via `json.parse_constant`), explicit JSON nulls anywhere, and duplicate physical ids; per-record shape validation with `Draft202012Validator` + `FormatChecker` (uuid/uri/date/date-time all actively checked — `rfc3987` and `rfc3339-validator` are dependencies so the format checkers are real, not silently skipped). Shape validation also rejects non-finite floats in in-memory dicts (not only JSONL input), and accepts optional top-level fields only when a caller names them from an evolved storage schema. Kind→table and table→mutation routing is derived from the schema's `x-iceberg` annotations — the schema is the single owner, nothing is hand-duplicated.
- `semantics.py` — `check_corpus(records)` enforcing the local C6/C7 invariants: foreign-key kind checks, run input coverage for outputs, `text_hash == sha256` of exact UTF-8 text, span bounds + surface equality on code-point offsets, tenure/affiliation interval validity, item supersede-chain acyclicity and `current_version` ownership, story/member run agreement and ≤1 membership per (run, version), release snapshot-table set completeness/uniqueness, snapshot-id int64 range, ≤1 selection per processor, ≤1 checkpoint per connector key, run `started <= finished`, run-input acyclicity, text only from succeeded non-metadata captures, the full identity decision graph (cycles, contradictions, authoritative-ID conflicts, retractions), and unredacted-credential rejection. `validated_ids` skips per-record shape/hash work for previously validated immutable snapshots while still running every cross-record rule. Every failure raises `ContractError` with a stable `rule` name and the offending `record_id`.
- The schema ships as package data (`contract/schema/`) and is loaded via `importlib.resources`.

### Slice 2 — storage (`src/news_lake/storage/`)

Real Iceberg v2/Parquet via pyiceberg 0.12 with a `SqlCatalog` (sqlite) and a local-filesystem warehouse.

- `mapping.py` — JSON→Iceberg schema conversion per I1 (timestamptz microseconds, dates, longs, doubles, structs, lists with non-null elements; required fields→required columns; `kind` is not a column). Record→Arrow row and row→JSON export (SQL NULL → field omitted; recorded empty arrays stay `[]`). Optional evolved Iceberg columns outside the JSON Schema round-trip by their Arrow type when the table schema supplies them; chained `$ref` resolution is supported.
- `catalog.py` — `Lake`: creates the `news` namespace and all 13 tables from the schema annotations; format-version 2; unpartitioned (I5). Table UUIDs come from the catalog. Writes always use the table's own schema so field ids are never regenerated from column order.
- `control.py` — sqlite control store: writer fence (epoch), durable intent journal, staged checkpoints, monotonic active cursor, publication-sequence registry, validated-snapshot cache, and release availability registry. Every mutator runs in `BEGIN IMMEDIATE` and checks the fencing epoch inside the write transaction, so a stale writer cannot slip a state change in after its pre-check. Operational state lives here; evidence lives in Iceberg.
- `coordinator.py` — fenced single-writer commit coordinator (I2): append tables treat a replayed identical row as a no-op and id reuse with different values as a hard `CommitError`; upsert tables (`outlets`, `items`, `entities`) merge by id — list evidence (aliases, domains, feed URLs, identifiers, tenures) always unions so earlier polls' evidence survives (C1), `first_seen_at` keeps the earlier instant, `recorded_at` keeps the later instant, and scalar fields only take the incoming value when the incoming poll is at least as recent (a late older poll cannot regress name, content type, outlet ownership, or `current_version_id`). Replacements commit `delete` + `append` in one Iceberg transaction, so recovery never observes a row-absent state. Incoming instants are canonicalized before dedup so schema-valid trailing-zero fractions replay cleanly. `abandon_cycle(cycle_id)` is the policy-deletion remediation for a failed publication cycle: it refuses to run once the release record is appended, refuses to wipe the warehouse when releases exist but none is available, discards that cycle's staged checkpoints, skips snapshot-identical tables, and restores changed tables atomically. Fault-injection hook (`Faults`) with `crash_before`/`crash_after` points: `journal_write`, `table_commit:<table>`, `upsert_replace:<table>`, `checkpoint_stage[:<connector_key>]`, `release_append`, `cursor_advance`. `recover()` converges journaled cycles idempotently (no exactly-once claim).
- `releases.py` — `publish_release` implements I3 exactly: commit candidate tables → validate C7 against those exact snapshots → stage checkpoints → append the release → mark it available → advance the cursor. The built release record is journaled immediately so a retry replays the same pinned snapshots rather than rebuilding drifting ones. A release names all 12 non-release tables with table UUIDs; `snapshot_id` is present only when the table genuinely has a snapshot (absent = explicitly empty, never "latest"). `read_release` resolves pinned snapshots and rejects unknown, unreleased, retired, UUID-mismatched, and missing-snapshot releases; it can read a validated table subset. Validation amortizes per-record shape/hash work for snapshots already validated by a successful release while every cross-record C7 rule still runs. `retire_release` flips the availability registry (I4).

### Slice 3 — RSS adapter (`src/news_lake/adapters/rss.py`)

Offline pipeline from fetched feed bytes to contract records (capture → discovery → item → version + extraction run), built on feedparser. Live HTTP wiring is deferred: callers hand over `FetchOutcome` objects. URLs are normalized only by lowercasing scheme/host and stripping the fragment, with originals preserved as aliases (C1); duplicate and same-publisher redirected URLs fold into one item (including redirect variants seen in later entries, with missing title/body backfilled), while a cross-domain canonical link never merges two outlets. Outlet domains fold common article subdomains (`www.`, `m.`, `news.`, `politics.`, etc.) with a public-suffix guard, so RSS/GDELT/Media Cloud agree on the outlet for `news.example.com` without turning `news.com.au` into `com.au`. Publication precision follows C3 (tz-aware time → instant; date-only or tz-less time → day; absent/unparseable → unknown — midnight is never invented), accepts RFC 2822 and ISO-8601/Atom timestamps, and records publisher-provided feed dates with `basis: 'publisher'`. Failed and not-modified fetches record `error_code`/no payload; blocked sources become `metadata_only` captures and versions without fabricated titles (C4/C5). IDs are deterministic (items from outlet+canonical URL, discoveries from capture+provider+external-id-or-URL), so replaying one captured result reuses every ID while a new successful poll is a new observation (C2). The default text processor is a minimal stdlib HTML→text extractor, documented as a placeholder.

### Slice 4 — identity (`src/news_lake/identity/`)

- `people.py` — five illustrative authoritative person entities covering the packet's hazards: a same-name pair of two different people, a renamed person (old name as alias), non-ASCII surfaces, and dated tenures (inclusive from, exclusive to).
- `decisions.py` — the decision-graph owner (C6): applies unretracted `same_as`/`different_from` decisions in `(recorded_at, id)` order; `same_as` maps left→right. The literal directed decision arrows and the Union-Find equivalence classes are separate structures, so cycle checks see every applied arrow (including confirmations) and multi-branch DAGs resolve deterministically without false cycle errors. Reflexive decisions, cycles, contradictions (a merge across a `different_from` pair, or distinction over equivalent entities), and authoritative-ID collisions (same scheme, different values) are rejected; a retraction must name an earlier non-retraction decision and un-applies exactly its target. Pure and replayable.
- `linking.py` — mention records with zero-based Unicode **code-point** offsets (exclusive end) into the exact version title/text. Matching keeps original surface lengths, verifies each candidate slice on the original haystack, and applies Unicode word boundaries, so casefold expansions (`ß`→`ss`) preserve spans and `Robin Roe` never matches inside `Robin Roebuck`. Candidates deduplicate by resolved root (merged same-name people resolve; genuinely distinct ones stay ambiguous); unresolved/ambiguous mentions carry no entity id; aboutness defaults to unknown.

### Slice 5 (offline core) — provider adapters (`src/news_lake/adapters/`)

- `cursors.py` — the pagination/cursor owner: a page's checkpoint becomes stageable only after the page's records fully commit (a fault mid-page leaves the cursor unmoved; replay converges), and the cursor never regresses on late-arriving older pages (their records still commit as evidence).
- `gdelt.py` / `mediacloud.py` — fixture-JSON response parsers honoring C1–C3 under the shared item namespace, so provider overlap shares items while each fetch stays its own observation. GDELT's `seendate` is acquisition, not publication: items record no `reported_publication` rather than a substitute (C3). Media Cloud `publish_date` keeps provider-contract UTC as an instant, degrades date-only and midnight-naive values to day, and leaves invalid/unparseable values unknown instead of raising. No live calls — the P1/P5 HTTP wiring stays deferred.

### Slice 6 — analysis (`src/news_lake/analysis/`)

- `cluster.py` — one deterministic baseline clusterer: versions group by SHA-256 of casefolded, whitespace-collapsed text; identical text across outlets is a syndication signal. The honest limitation is in the contract: such clusters do not prove independent reporting or permanent event identity (C9).
- `selection.py` — the C8 owner: per (input, processor), the latest successful run by `(finished_at, id)` matching the release-pinned (processor, version, config) triple; a later zero-output success replaces an earlier run's outputs; unprocessed inputs stay visibly pending, excluding captures no extractor could consume (failed, not-modified, metadata-only) and versions no clusterer could group (no text). `current_version_id` is not derived here — items explicitly select their text.
- `views.py` — the C9 owner, release-scoped: `politician_articles` keeps at most one row per (resolved person-root, current item, release), follows supersede chains to the survivor, counts only the release's selected runs' mentions, honors the release's pinned identity decisions by default, retains version/run ids and aboutness, and unions overlapping spans across aliases (adjacent spans stay separate); `coverage_daily` counts distinct items/outlets/stories per publication date with unknown dates forming one undated group, falls back to unambiguous discovery-reported publication for versionless items, and lists identical-text groups as syndication visibility — never as independent-reporting counts. Both views record their source release id.
- `labels.py` — a deterministic keyword baseline producer for typed classifications (`topic` and `tone`), explicitly documented as uncalibrated and method-specific (C6); it emits run + classification records for versions with text so C8 selection can consume them.
- `export.py` — the C5 export gate: `export_release` deep-copies a pinned release and omits restricted/expired bodies and payloads unless the caller is authorized, while preserving redistributable content and all identifiers.

## Seams and known limitations

- **`arrow_patch.py` (pyiceberg 0.12 bug):** pyiceberg's `ArrowProjectionVisitor.list` rebuilds list-of-struct arrays via `from_arrays(offsets, values)` (its workaround for apache/arrow#38809), dropping the validity bitmap — a NULL list column was written to Parquet as `[]`, collapsing "optional field absent" into "recorded empty array" (which would corrupt e.g. `classification.value_strings` on export). The seam patches that single rebuild to pass `mask=`; everything else is stock pyiceberg. The patch applies only on pyiceberg `0.12.*` (a version guard skips it elsewhere) and is pinned by the `<0.13` dependency; remove when fixed upstream — the round-trip tests fail without it.
- The catalog assigns persisted field ids at `create_table`; they are stable for a warehouse but not identical across separately created warehouses. The mapping's build-time ids are placeholders and the table's schema is authoritative for writes.
- Crash recovery assumes the single-writer discipline of I2: a journaled cycle is retried by `recover()` without interleaved acquisition through the same coordinator. Work that crashed *before* the journal write is, by design, unknown to recovery and must be re-submitted by the caller (the tests model this).
- Writer fencing is atomic across both sqlite and Iceberg: `ControlStore` mutators run in `BEGIN IMMEDIATE` and verify the fencing epoch inside the write transaction, and `Lake.fenced_commit` holds that same `BEGIN IMMEDIATE` fence lock across `SqlCatalog.commit_table` when swapping the Iceberg table metadata pointer in `catalog.db`. A stale writer cannot slip a control-store mutation or a catalog metadata commit past a newer lease holder.
- Upsert replacements are a single Iceberg transaction (`delete` + `append`), so there is no row-absent intermediate snapshot. A refused/replayed cycle still converges from the journal.
- `abandon_cycle` rolls back a failed cycle by restoring each changed content table to the exact row set pinned by the latest available release (removing newly added rows, including pre-committed `PageDrain` rows, and restoring pre-cycle rows for any upsert IDs the failed cycle touched). It refuses to wipe the warehouse when releases exist but all are retired, and it refuses a cycle whose release record was already appended; recovery owns that case. Full retention/expiry per C5/I4 beyond the C5 export gate, `retire_release`, and `abandon_cycle` is still deferred, as are snapshot expiry and compaction.

## Deferred (not implemented here)

Matching the packet's own candor (`04-implementation-plan.md`): live provider HTTP wiring (real RSS polling, Media Cloud/GDELT requests, credentials beyond URL redaction), the production extractor choice (the stdlib HTML→text extractor is a placeholder), full retention/expiry enforcement beyond the C5 export gate plus `retire_release` and `abandon_cycle`, compaction/partitioning at measured volume (I5 tuning), the production classification model beyond the deterministic keyword baseline, the pilot's five-politician roster, and the pilot's audited 30-day coverage/latency measurement. `docs/adr/news-lake-contract.md` proposes the packet as the contract authority with the pilot report as the ratification gate.

## Layout

```
packages/news_lake/
  pyproject.toml
  src/news_lake/
    contract/           # schema copy (package data), records, semantics, errors
    storage/            # mapping, catalog, control, coordinator, releases, arrow_patch
    adapters/           # rss, gdelt, mediacloud, cursors, shared provider plumbing
    identity/           # fixture people, decision graph, mention linking
    analysis/           # clusterer, baseline labels, C5 export, C8 selection, C9 views
  tests/                # offline: sqlite + local files under tmp_path
packages/news-lake/docs/ # read-only packet authority (schema, fixtures, checker)
```

## Running the tests

```
.venv/bin/python -m pytest packages/news_lake/tests -q
```

Fully offline: sqlite catalogs and local-filesystem warehouses under `tmp_path`. The suite covers the slice exit gates: docs fixtures pass plus negative shape/corpus cases; non-finite and credential rejection; schema-copy identity; per-kind round trips; replay dedup and append collisions; atomic upserts and crash at every injected point → prior release readable → recovery converges to the uninterrupted state; publish-last ordering (invalid batch ⇒ no release, cursor unmoved); pinned reads, explicitly-empty tables, unreleased/retired-release rejection, old-release snapshot isolation; and schema evolution (optional column added with a real value, field ids preserved, old pinned snapshot readable). Adapter and identity gates: RSS redirect folding/duplicate URLs/ISO and RFC dates/blocked fetch/metadata-only/cross-domain no-merge/replayed-capture id reuse and new-poll new-observation; feed→release round trip; decision DAG cycles/contradictions/authoritative-ID conflicts/retract-reversibility; casefold-safe, word-bounded mention spans with code-point (non-UTF-16) offsets; cursor advancement only after commit, cross-cycle non-regression on late/backfill pages, mid-page fault convergence, quota errors; cross-provider item sharing. Analysis gates: identical-text clustering determinism; changed-model and zero-output selection, pending visibility; the C9 views (one row per person-root/current item/release, survivor counting, selected-runs-only mentions, overlapping-span union with adjacent spans preserved, discovery-date fallback, undated group, syndication visibility); deterministic typed labels; and the C5 restricted/expired export gate.
