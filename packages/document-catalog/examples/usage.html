Build a reusable document catalog from retained files

This package hashes source bytes, captures PDF pages, measures text and geometry, proposes layout groups, and exports reviewable plans and fixtures. Categories supply their own prompt vocabulary, semantic roles, and JSON/XML schema references. It does not extract fields or establish field accuracy.

Install and run

python3 -m venv .venv-catalog
.venv-catalog/bin/pip install './packages/document-catalog[vision,layout]'
.venv-catalog/bin/document-catalog init-config --output category.json
.venv-catalog/bin/document-catalog run --input /retained/documents --output /catalog --config category.json --workers 2
.venv-catalog/bin/document-catalog status --catalog /catalog
.venv-catalog/bin/document-catalog validate --catalog /catalog

Use --manifest inputs.json instead of, or alongside, --input. A manifest contains {"sources":[{"path":"relative-or-absolute-path","filename":"source.pdf","sha256":"optional-decoded-source-digest","url":"optional-provenance"}]}. Relative paths resolve against the manifest directory. Gzip files are decompressed before source hashing, and the compressed transport digest is retained. Unsupported formats and source failures stay visible. Directory discovery includes all files; an optional selection.filename_regex records nonmatching entries explicitly.

Exit code 0 means processing or validation completed, 1 means a command/validation error, and 2 means a partial catalog was published with failures or unsupported formats. A processed catalog can still have unresolved semantics. An empty selection has the separate no_matches status.

Choose local observations

PDF capture uses PyMuPDF. Native coordinates are rotated into rendered-page orientation and normalized to top-left [left,top,right,bottom] values between zero and one. Original point boxes and transforms remain available. Vector rules, image areas, and form widgets are measured separately.

ocr.mode supports auto, always, or never. Automatic OCR runs for sparse native text, measured encoding symptoms, or substantial embedded images. Printable corrupt font mappings can evade those symptoms; use always when native text must be independently reread. OCR uses native Apple Vision on macOS. It retains raw observations, confidence, image identity, revision, and coordinate conversion. Empty results and failures remain unresolved; failures preserve native text as an unverified fallback. No Tesseract execution exists.

For local Docling layout predictions, set layout.provider to docling and layout.artifacts_path to an existing local model directory containing config.json, preprocessor_config.json, and model.safetensors. The adapter uses Docling's docling-ibm-models.LayoutPredictor API with CPU inference. Model bytes are hashed and network model downloads are disabled. This package does not install or download models. layout.provider: none retains native/OCR geometry and leaves model predictions disabled.

Import predicted sections

The default document plan contains measured or predicted layout regions, candidate reading order, original page adjacency, vector primitives, configured prompt/role proposals, and explicit unknown semantic sections. Prompt boxes describe prompts and do not bound answers. A local model or another authorized reviewer can consume these plans, rendered pages, and original sources. This package makes no semantic model calls.

document-catalog import-plans --catalog /catalog --batch predictions.json

Start with model-plan-batch.json. Copy the current catalog digest from current.json and document/source/context values from exported plans.json. Every part needs real page-local text or layout item IDs from pages.json as evidence_refs. Bounds are predicted section bounds; references must intersect them. Part order follows source pages, while the supplied within-page order is preserved. A multipage or multiregion section requires a continuation link for every adjacent part, with evidence at both ends. Attachments and subsections use parent_section_id plus relation: attachment|subsection.

Retain the provider/model revision, exact prompt, raw response, parameters, actor, method, and timestamp in model provenance. For manual bounds use kind: manual with actor/method/timestamp. A later model prediction cannot replace an existing manual plan; its evidence still enters history. Every page must have a section or appear in unresolved_pages. Separate unassigned_region_ids keep small imported sections from implying full-page coverage.

Imported bounded sections produce candidate section-pattern groups and profiles using part geometry and stable prompt evidence. Their semantic roles do not partition the groups. Schema bindings identify future extraction schemas; schema existence, validity, and field accuracy are not independently checked here.

Review without erasing evidence

document-catalog review --catalog /catalog --batch judgments.json

Start with review-batch.json. Copy target IDs and contexts from review_targets.json. Batches are validated completely before mutation. Human and agent judgments stay distinct. Decisions are accept, reject, or uncertain. Historical judgments remain visible as active, superseded, or stale. A section's context includes its content and plan provenance, so changed bounds invalidate previous acceptance. Automatic unknown counts remain visible after reviews.

Resume and inspect

Repeat the same run command to reuse verified successful stages. Add --retry-failed to append new attempts for failed or partial stages. Source changes, configuration changes, runtime versions, model bytes, or implementation changes invalidate affected cache keys. Existing evidence and snapshots remain immutable. One writer owns each catalog directory; a bounded process pool handles distinct documents.

current.json points to an immutable catalog and export manifest. Each exports/<catalog-id>/ directory includes lossless JSON, Parquet with typed scalar columns plus lossless record_json, representative fixture manifests, page/document/section plans and candidate groups, review targets/history, and a self-contained report.html. Fixture expected fields are null and gold status is unlabeled. The HTML embeds page thumbnails and layout overlays, with no external scripts or remote image requests.

validate checks retained source/artifact/export digests, aliases, page counts, geometry, group accounting, and section references/continuations. It does not certify reading accuracy, semantics, reusable templates, or field extraction. PDF is the implemented format. Other formats remain inventoried with unsupported_format and no invented page geometry.
