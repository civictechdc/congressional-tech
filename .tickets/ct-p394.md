# Reading evidence hashes house_naming/Engine.py only on a case-insensitive disk

Found by congress-1's sixth MODS review; measured 2026-11-11 09:49Z on aff628e7 (.cache/archive-release/investigations/docspec-feedback-20261110/refactor/evidence-case/ec_case_scan.json). ImportClosure._workspace_path (lake/versions.py:154) also treats 'from X import Name' as a possible submodule X.Name, and accepts the file when Path.is_file() says yes. On macOS's case-insensitive APFS, house_naming.Engine (imported by meeting_records.py:689, filenames/__init__.py and house_naming/naming.py) resolves to house_naming/Engine.py. That is the same file as engine.py, which the package __init__ already imports, but PosixPath compares names case-sensitively, so it is hashed a second time under the name Engine.py. On Linux no such file exists. The body-text readers' evidence (pdf_text, html_text, xml_text, warc) is therefore stamped on the Mac with one extra file entry, and a Linux doctor (hosted CI) computes a different workspace_sha256 and warns (exit 0). The whole workspace has one other case-only resolution: committee_meeting.Catalog to Catalog.py (committee_explorer assemble.py and issues.py), in no reading closure. Producer identities do not move: producer_version uses only the walk's package names, and both twins import nothing new. Fix: resolve a submodule only when a file of exactly that name is listed in its directory. The resolution lives in lake/versions.py, which the docspec-feedback refactor team may not edit, so the fix waits on the coordinator releasing that file.

## Acceptance Criteria

Test first: a temporary package with engine.py imported as Engine; on a case-insensitive disk the walk reaches no Engine.py (fails before the fix), plus one planted case. Producer identities are unchanged (the test_*_version pins pass). The four body-text workspace_sha256 values are re-stamped once on the Mac with an equivalence note and then equal what Linux computes. doctor shows no reading warnings on the Mac.
