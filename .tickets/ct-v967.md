# Raw data safeguards (Oct 24 audit)

Only the raw objects in R2 `congressional-tech-raw` under `bodies/`, `receipts/` and their provenance must survive; everything else can be rebuilt. This epic holds the raw-data actions from `docs/reviews/2026-10-24-ticket-audit/README.md` ("Raw-data status", "Actions taken on Oct 24", "Raw-data risks"). It is separate from the simplification epic because these are data checks and owner actions, not code cuts.

Owner decisions: an R2 bucket lock on `receipts/`, `bodies/` and `provenance/`, with one bucket; wrong `stored_sha256` rows are repaired in place rather than by regenerating the index.

## Acceptance Criteria

- Bucket lock rules are on and read back.
- The capture index holds no row with a wrong `stored_sha256`.
- `accepted.json` and the receipts are reconciled, with the result committed under `docs/`.
- A scheduled capture has run since the fixes and written correct digests.
