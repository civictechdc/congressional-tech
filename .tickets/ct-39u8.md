# Org entities phase 3: Wikidata reconciliation receipts, auto-accept and review queue

Size L. Plan: docs/plans/org-entities-20261108.md (Pipeline steps 3-6, 10; Wikidata acceptance). New capture family wikidata/reconcile (capture-scope.json, receipt-line-kinds.json, recheck-intervals.json, no automatic recheck); model SQL org-reconcile-requests.sql emits batched canonical GET URLs as a capture_schedule campaign seed; capture with the fixed anonymous User-Agent; reading wikidata-reconcile-bodies.sql versioned in reading_versions; acceptance org-wikidata-links.sql. Auto-accept: unique top candidate with score >=90 (24/24 correct, wd_accept.txt). Review band: other candidates >=80, queued by appearance count in org_review_queue; never published as links. Measurement: entity-matching-measure-20261108/org_score.json, org_labels.json, org_hand_check.txt, em-wd-accept.py -> wd_accept.txt.

## Acceptance Criteria

1) Every Wikidata answer used is a retained capture receipt; the model reads no live endpoint. 2) Requests are incremental: only cores without a receipt. 3) Before auto links publish: a fresh hand label of 150 auto-accepted links (not the 60 seeded rows), stratified by appearance band, finds <=3 wrong. 4) Report reach by appearances and by strings, plus review-queue size. 5) A different decision on (string, Q) blocks that link on the next rebuild.
