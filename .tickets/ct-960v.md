# Keep items Congress.gov drops from a meeting on the page, marked 'no longer listed', instead of removing them

Owner decision 2026-11-11 (session congress-1, questions dialog), asked while reviewing ct-rhqw ('everything from Congress.gov publishes'): the owner asked 'we shouldn't replace/delete, we should reference, right?' and chose 'Keep it, marked no longer listed': when Congress.gov drops a witness or a document from a meeting, the published page keeps it, marked 'no longer listed by Congress.gov since <date>', and its link keeps working; the raw archive already keeps every read. Today the release shows only the publisher's current list and a removed witness's key maps to a successor or 'unresolved' (a lost key), which under ct-rhqw stops the night. With this, removals never lose a key, so those nights publish unattended. Fits the carried witness keys (ct-46f3): a carried key whose entry vanished stays published as a no-longer-listed row instead of becoming a map row; edits keep their key by carry. Scope: a listing state on witness rows (and on a meeting's document membership) with the date it was last seen listed and the read that stopped listing it; site and Explorer display; the release schema; the gate then treats a vanished Congress.gov key that is kept as no-longer-listed as answered. Other sources (MODS, House XML, Senate pages) decided separately.

## Acceptance Criteria

A witness or document Congress.gov stops listing stays on the meeting page marked 'no longer listed' with the date; its key and links keep resolving; no witness key is lost on a re-fetch night; a raw check compares each no-longer-listed row with the earlier read that listed it and the later read that does not; planted cases (a still-listed item marked removed; a removed item dropped) are flagged.
