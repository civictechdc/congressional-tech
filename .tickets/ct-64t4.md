# Decide the nightly model's engine limits: it runs at 24 GiB and 2 threads from the Mac remote runtime, above the 14 GB watchdog

Found 2026-11-10 while diagnosing ct-n5ec. model/jobs/publish-model.json names engine_config ../../.runtime/docspec/runtime.json, which does not exist, so archive_publish_job.py falls back to DOCSPEC_RUNTIME_CONFIG, the Mac remote runtime; its limits.json says memory_bytes 25769803776 (24 GiB), compute_threads 2, scratch 64 GiB. So the query pool is 12 GiB and the retention pool 3 GiB, not the 7 GiB that .github/docspec-local-limits.json implies, and the engine's own limit is above the watchdog's 14 GB kill line (nightly peak RSS 10.4 to 11.2 GiB). Nobody has recorded whether the fallback is intended. A thread-count measurement was started 2026-11-10 13:17Z: the 147-step model prefix to base_normalized at 2, 4 and 8 threads on the pinned engine with output hashes compared (.cache/archive-release/investigations/thread-measure-20261110/). More threads mean more partitions, which changes hash-join build accounting, so the pool figure matters as much as the clock.

## Acceptance Criteria

The fallback is either made explicit (the spec names the runtime it uses) or removed, with the reason recorded. The memory limit and the watchdog limit are consistent on purpose. The thread measurement is recorded with wall time, peak RSS, pool peak and output hashes per thread count, and compute_threads is kept or changed by an owner decision with a full-size build confirming identical outputs.
