# Gate report names the removed keys behind a stopped night

A capture night stops for a cause record whenever any key is removed (data_only_night.EXPLAINABLE covers additions only, by design). On 2026-11-18 (run 44303486024, base eb6710bb1a14) the only reason was recording_matches.parquet|removed keys|no evidence given (-1); the same single removal stopped the night into 2ec7ae83a852 on 2026-11-17. Two of the last three capture nights, each for one replaced video-to-meeting match.

The report gives the count and nothing else, and the candidate is not public until it publishes, so the person signing the record cannot see which match went or why without rebuilding the model.

1. Evidence, not a cap change: when a removed-keys group is small (say 20 or fewer), release_comparison writes the removed key values into the gate report, so the signer can look the row up in the live release.
2. After seven scheduled nights of numbers (owner rule: leave tripwires alone until then): if the removals are always a match replaced because its recording's event_ids changed (recordings.parquet changed event_ids was 4 on 2026-11-18), add a traced proof for that shape so those nights publish unattended.

First check whether release_comparison.py is in the model definition hash; if so the change itself needs a cause record.

## Acceptance Criteria

A stopped night's release-gate.json lists the removed keys of each small removed-keys group; a test plants one removal and reads it back from the report.
