# Use retained HTML metadata to improve hearing discovery and document browsing

Users need reliable hearing dates, useful document descriptions, cleaner testimony content, and a clear distinction between when a hearing occurred and when its webpage changed. Add extruct-based interpretation to the existing retained-source pipeline and carry selected facts through publication to the site and MCP consumers.

The 2026-10-30 audit examined 185,698 distinct retained HTML bodies. It confirmed 936 listing-date errors against displayed row dates on 49 Senate listing bodies, found 177 encoded-time/visible-PM conflicts in that sample, and found 4,180 bodies with marked article/testimony content. These are body/entry occurrences, not counts of newly discovered or uniquely affected hearings. Nine extractions were partial by format. Existing code uses lxml and already retains raw HTML/JSON-LD.

User value: find the right hearing, understand what a document is, distinguish event dates from page updates, and inspect the evidence behind disputed values.

Evidence: docs/experiments/extruct-metadata-20261030/report.md and summary.json. Full extraction and comparison artifacts are under output/extruct-metadata-20261030/ (local, Git-ignored); preserve portable fixtures and manifests needed for tests rather than relying solely on these local paths.

## Design

Deliver in three increments: (1) shared extraction and listing correctness; (2) cleaner content, selective retained-body replay, semantic mapping, and publication; (3) site/MCP consumption and end-to-end qualification.

Owners: congress_api parsers/lake/adapters; committee_meeting; model/ and viewer_publication; the maintained committee_explorer exporter if still an active consumer; apps/site; apps/explorer_mcp. Reuse Keeplist's raw-metadata preservation and repeated-value handling in a thin congress_api adapter. Reuse existing ReportedTime, Location, provenance, issue, and material-date fields. Add only the optional publisher description needed by the first release.

Extract body facts once per body and version; resolve relative URLs per capture context. Preserve original bytes, date precision, contradictory declarations, and partial-format errors. Page metadata does not automatically establish event identity, witness participation, document equality, or successful source access.

Related work: ct-gi01 owns the Explorer/native export migration. Extend the maintained publication path at implementation time; do not create another writer or revive retired viewer routes. The user-requested metadata UI scope is grounded in this corpus audit; ct-2wsw's unrelated performance work remains outside scope.

Deferred: preview-image selection, social-account discovery, a generic extraction framework, a full-text search platform, GovInfo source changes, and replacing the existing YouTube API metadata path. Creating these tickets does not publish a release or initiate a crawl.

## Acceptance Criteria

- All child tasks are complete with package-owned implementation and evidence against one recorded code revision and input snapshot.
- The retained listing cohort demonstrates correct row/date association and explicit treatment of encoded/displayed time conflicts; no claim that the audit established wrong stored hearing identities.
- Selected dates, descriptions, document labels, and content readings retain source pointers through real publication and both consumers.
- Unchanged bodies reuse versioned readings; source bytes, unrelated inputs, and established identities survive reprocessing.
- Acceptance distinguishes local fixture checks, retained-corpus measurements, and any separately executed live publication. Missing evidence remains explicit.
- Record the final package changes, before/after user outcomes, resource measurements, unresolved extraction limits, and supported release schemas.
