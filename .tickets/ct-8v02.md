# Offload browser sources.parquet payload JSON to R2 (Option 1B), eliminate 24.45 MB PDF-in-Parquet & 275 MB upstream/lines bloat, and normalize title/facts/links/identifier columns

Raw data audit of committee-explorer release ca4748be7105a94345815382 revealed:
1. A 24,452,625-byte (24.45 MB) binary PDF cell (id=d2dc516a-7af6-4950-a68f-712d1de28802, url=https://www.intelligence.senate.gov/wp-content/uploads/2024/08/sites-default-files-hearings-105290.pdf) is still inside sources-3.parquet (5.59 MB ZSTD compressed = 16.5% of the file for 1 row), containing 4,801,258 U+FFFD replacement characters inside payload.lines. senate.py:25 decoded raw PDF bytes with errors='replace'; assemble.py detected the bad PDF and emitted a DataIssue into issues.parquet, but kept the full 24.45 MB lines array on SourceRecord.payload, and ct-f7p8 accommodated it in pipeline.rs instead of rejecting it.
2. Across sources-1..3.parquet (308,516 rows, 121.49 MB compressed / 596.90 MB uncompressed), payload accounts for 92.3% of the table (538.9 MB uncompressed / 112.1 MB compressed), including 43.71 MB of Senate scraped page lines across 5,356 rows, 221.02 MB of YouTube upstream envelopes, 10.78 MB of GovInfo upstream blobs (up to 1.65 MB/row in CHRG-118shrg64466), and House XML/HTML source_bodies — none of which are ever read by the browser UI (apps/site/src/components/explorer/browse/record-presentation.ts:465-760).
3. Meanwhile, retained_uri and retained_sha256 in sources-1..3.parquet are 100.0% NULL (0 / 308,516 rows), even though SourceRecord (provenance.py:11-42) and the React UI (record-presentation.ts:415, 1440-1455) were explicitly designed to link to R2 content-addressed objects (/bodies/sha256/<xx>/<sha256>.{gz,pdf}).

## Design

Implement Option 1B with full columnar normalization:
1. In apps/committee_youtube/src/committee_explorer/parquet.py (SOURCE_SCHEMA, _source_row), replace the raw JSON payload column and JSON-encoded identifier string with normalized typed columns matching the rest of the browser tables:
   - id, provider, title (extracted using RecordDetail.tsx:29-35 rules), url, retrieved_at, source_modified_at, imported_at, input_snapshot_id
   - identifier_scheme, identifier_value, identifier_scope (normalized from SourceRecord.identifier)
   - retained_sha256, retained_uri (pointing to /bodies/sha256/{sha[:2]}/{sha}.{gz,pdf} in R2 via physical_body_object_key)
   - facts: list<struct<label: string, value: string>> (normalized at build time using sourceFacts() rules in record-presentation.ts:465-700)
   - links: list<struct<group: string, label: string, href: string>> (normalized at build time using sourceLinks() rules in record-presentation.ts:724-760)
2. Write raw SourceRecord payloads / scraped bodies directly to R2 content-addressed storage (/bodies/sha256/{sha[:2]}/{sha}.{gz,pdf}) and populate SourceRecord.retained = RetainedContent(uri=..., sha256=...).
3. Update apps/site/src/components/explorer/view/RecordDetail.tsx, browse/record-presentation.ts, and reader/parquet-source.ts to render row.title, row.facts, and row.links directly from sources.parquet without JSON.parse(row.payload), and fetch /bodies/sha256/{sha[:2]}/{sha}.{gz,pdf} from R2 on demand only when a user clicks 'Open saved original' or expands 'See everything saved' (RawRecord).
4. In packages/congress_api/src/congress_api/retention/senate.py:25 and assemble.py, reject %PDF- magic bytes and high U+FFFD replacement-character density in HTML/text scrapers (storing PDFs as .pdf objects in R2), and enforce a 256 KiB max string cell guard on browser Parquet tables.

## Acceptance Criteria

1. sources.parquet has zero raw payload JSON column and zero >256 KiB cells; the 24.45 MB PDF cell is completely absent from Parquet.
2. retained_sha256 and retained_uri are populated on 100% of rows in sources.parquet and resolve to content-addressed R2 objects (/bodies/sha256/<xx>/<sha256>.{gz,pdf}).
3. All display facts (sourceFacts), links (sourceLinks), title, and identifier fields (scheme, value, scope) are normalized into typed columns on sources.parquet and rendered losslessly by RecordDetail.tsx.
4. Assembly-time selector validation (export.py:validate_selectors) and appearance reuse (recovered.py) continue to pass.
