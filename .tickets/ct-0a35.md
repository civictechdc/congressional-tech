# Verify repaired readings through release-bound full-text search

Completed extraction and a successful index build do not show that users can find repaired content. After a release includes accepted markup/cleanup replacements, check representative names, dates and passages through the actual full-text-search consumer and reopen their citations. ct-m704 owns the body-text export/index and search delivery; this ticket owns bounded source-to-search acceptance, not a second index implementation.

Reuse the source-quality example inventory and existing directly reviewed repair/control cases. The target is useful searchable content, not perfect transcription or a corpus-wide manual audit.

## Design

Freeze the release, selected actual reading keys, text hashes and index coverage. Select a small documented mix of repaired HTML/XML, retained PDF cleanup/native cases where accepted, legitimate short/blank/metadata controls and known error responses. Prepare query expectations by directly reading the raw/intermediate/output material, then run the maintained search_text/reader path and reopen returned body/page/offset or citation references. If the target release has no usable index, record that missing prerequisite rather than reporting a pass. OCR remains paused and publisher refetch deferred.

## Acceptance Criteria

1. Name the tested release/index, coverage and exact selected reading/output identities; distinguish local candidate checks from published consumer readback.
2. Representative source-confirmed names, dates and substantive passages return the intended document and a snippet that agrees with the selected output. Reopened citations resolve within the same release and source scope.
3. Known error responses are not presented as substantive hearing/document content, while ordinary short and metadata/landing controls retain appropriate behavior. Explain legitimate exclusions and every failed expectation.
4. A named reviewer directly reads the raw -> actual intermediate -> selected output -> search result chain for the bounded sample. State unread pages/records; scripts alone do not establish content accuracy.
5. Demonstrate that an omitted passage, stale selected hash or deliberately wrong snippet is detected. Report remaining exceptions and file cause-specific follow-ups; do not require a 200-body calibration study or any OCR/refetch restart.
