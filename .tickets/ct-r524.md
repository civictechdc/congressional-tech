# fast-gemma4 seven-chunk ANE ring: two identical runs differ on 6 of 212 docs (topics, gist)

Measured 2026-11-17 on fast-gemma4 edd577a (now in main as b725b87), model gemma4_e2b_v64_c2c4_w8, sets valid_sweep,val48_sweep with --ane-ring: runs chunks7_ring and chunks7_ring_r2 differ on 6 of 212 docs, only in the free-text fields topics and gist; every scored metric agrees to 0.1. The three-chunk ring on 46b0207 gave identical output on all 212 docs in four runs over two days, at machine loads from 29 to 87; so did the pad-fix ring (three runs) and GPU only (two runs each). Timing alone did not move the old code, so the variation arrived with the seven-chunk change. Reports: fast-gemma4 artifacts/eval/ring_followups_20261117/. Not investigated. Guess, unverified: with seven chunks the ANE is busy longer, so which docs share a GPU tail group or a decode batch depends on timing. A race in ring-slot bookkeeping is less likely (KV check after a seven-chunk admit showed at most 3 wrong window positions per doc) but not ruled out. Matters because resumed or repeated sweeps of the 258,440-row queue would not reproduce byte for byte.

## Acceptance Criteria

1. The cause is named with evidence (for example cohort and tail-group membership logged for both runs and compared on the 6 docs). 2. Either two back-to-back seven-chunk runs give identical output on the 212 docs, or the variation is shown to be confined to free-text fields and recorded as accepted in the measurements note. 3. If it is a bookkeeping race, a CPU regression test covers it.
