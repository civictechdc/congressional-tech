# The import job checks for a clean checkout only after it has created and filled the lake table

Found by the independent review of the MODS appearance activation (2026-11-11, .cache/archive-release/investigations/mods-backfill-activation-20261111/review/). archive_import_job.py creates and appends to the new lake table (:174, :181) and only then reaches the clean-tree check (:112 via :191). On a dirty checkout the import creates and fills the table but writes no producer record, and a rerun refuses because the table now holds rows (:166), so the table name is spent. The record-only backfill job checks writer identity at the start of its run; the import should do the same. The activation runbook works around it with an explicit 'git status --porcelain' check right before --execute.

## Acceptance Criteria

The import job calls writer_identity (clean tree, commit reachable as required) before the target lookup and the create, and again after the write; a test with a dirty tree shows no table is created; the runbook's manual check can then be removed.
