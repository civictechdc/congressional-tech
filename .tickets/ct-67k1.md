# Show the publisher’s description and role for meeting documents

Readers following a meeting or witness document should be able to tell what it is and why it appears. The archive already links these documents, but public rows omit Congress.gov's per-link role, format, description and name. SpicyRegs needs the same fields to use the archive as its source for these links.

## Root cause (2026-11-05)

Congress.gov supplies typed document objects in `meetingDocuments` and `witnessDocuments`. The meeting-record extractor flattens both collections to distinct URLs before writing the typed meeting-record table. That loses the fields, the source collection and distinct references that share a URL. Downstream archive title or saved file format describe the document or resolved body and cannot recover the publisher's link attributes. For example, the event `100031` source fixture labels a link as `Support Document`, format `PDF`, name `Printed Hearing Record`, with no description supplied.

## Smallest useful change

Keep the supplied fields on the existing source relationship using typed, nullable values. Use an existing release field or a companion keyed to that relationship. Preserve the meeting or witness context and reuse the normalized URL lookup. Replay the affected retained Congress.gov meeting records and dependent release outputs. Check the shared schema's parser-version effects before carrying forward any other source family.

## Acceptance Criteria

- For meeting and witness document references with supplied metadata, the release exposes Congress.gov's `documentType` as role, plus format, description and name. The schema identifies the source and explains missing values. Keep publisher link format distinguishable from the format of the resolved body.
- Compare values through the existing SpicyRegs `ss-ikn9` comparison by normalized URL and source relationship. Account for matched and unmatched references and mismatches, preserve all existing meeting and witness links, and verify that distinct source references sharing a URL keep their own values.
- Check a supplied value and a source-omitted value in the retained records. Compare a record at the typed input boundary with the published result so the check detects a value dropped during extraction as well as during publication.
