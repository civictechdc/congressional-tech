# Show the publisher’s description and role for meeting documents

Readers following a meeting or witness document should be able to tell what it is and why it appears. The prior archive links these documents and omits Congress.gov's per-link role, format, description, and name. SpicyRegs needs the same fields to use the archive as its source for these links.

## Root cause (2026-11-05)

Congress.gov supplies typed document objects in `meetingDocuments` and `witnessDocuments`. The prior meeting-record extractor flattened both collections to distinct URLs before writing the typed table. That discarded the fields, the source collection, and distinct references that shared a URL. Downstream archive title or saved file format describe the document or resolved body and cannot recover the publisher's link attributes. For example, the event `100031` source fixture labels a link as `Support Document`, format `PDF`, name `Printed Hearing Record`, with no description supplied.

## Merged implementation and remaining acceptance

Local `main` includes the implementation at merge `18049548`. Typed `document_references` preserve the publisher’s link metadata, collection, and source order. Existing URL lookups continue to resolve the document, and references that share a URL retain their own fields.

The exact record-only refresh is staged with a verified producer record at `75c99254` and output SHA-256 `475fa09b5ed1076e5590158245ee13118bff656dc8c95f40533eaaf3bb171523`. The stage preserves all prior meeting fields. All eight retained references matched through the typed input and native output using the SpicyRegs URL lookup and source relationship. Event `100031` kept `Support Document`, `PDF`, `Printed Hearing Record`, and a null description. The duplicate-URL fixture preserved both references.

The release coordinator owns validating the input pins at the joint freeze, importing the verified stage, and running the full `ss-ikn9` comparison and selected-release reader checks. [Release follow-through](../docs/plans/production-mvp-follow-through-20261105.md)

## Acceptance Criteria

- For meeting and witness document references with supplied metadata, the release exposes Congress.gov's `documentType` as role, plus format, description and name. The schema identifies the source and explains missing values. Keep publisher link format distinguishable from the format of the resolved body.
- Compare values through the existing SpicyRegs `ss-ikn9` comparison by normalized URL and source relationship. Account for matched and unmatched references and mismatches, preserve all existing meeting and witness links, and verify that distinct source references sharing a URL keep their own values.
- Check a supplied value and a source-omitted value in the retained records. Compare a record at the typed input boundary with the published result so the check detects a value dropped during extraction as well as during publication.
