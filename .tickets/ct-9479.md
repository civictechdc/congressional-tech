# hearing_dossier recipe lists superseded witness appearances (double-counted panels)

The hearing_dossier recipe in model/registries/release-schema.json selects witnesses with WHERE w.event_id=m.event_id and no superseded_by IS NULL filter, while the documents subquery does filter hidden rows. Multi-source appearances (congress.gov + MODS) supersede each other, so the dossier lists each person twice. Verified on release e4538f00: event 105739 (Fentanyl: The Next Wave of the Opioid Crisis, 115th) returns 12 witness rows of which only 6 have superseded_by IS NULL. superseded_by appears in the registry only as a witnesses column (line 939), never in recipe SQL. witness_documents and witness_transcripts take a specific witness_key, so a superseded key still resolves — decide whether those recipes should surface supersession. Discovered via chaos run chaos-congress-mcp-20261103 and confirmed against checkout source in review.

## Acceptance Criteria

hearing_dossier returns current appearances only (superseded_by IS NULL), or exposes an explicit current/superseded distinction rather than silently listing both. A fixture hearing with known supersession proves the filter. Registry expectations updated where recipes are tested (apps/explorer_mcp/tests/test_relationships.py). The witness_key-scoped recipes state their supersession behavior explicitly.
